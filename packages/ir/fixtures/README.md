# Conformance-фикстуры IR

Общий набор примеров для всех реализаций валидатора IR (TypeScript — `@cms/ir`, Go — `apps/server/internal/composition/ir`), требование IR-005.

## `valid/`

Каждый файл — документ IR. Валидатор ДОЛЖЕН вернуть пустой список диагностик.

## `invalid/`

Каждый файл:

```json
{
  "description": "Что нарушено и какое требование спецификации",
  "expect": [{ "code": "NODE_ORPHAN", "pointer": "/nodes/n_lost" }],
  "document": { "...": "..." }
}
```

Валидатор ДОЛЖЕН признать документ невалидным и для каждого элемента `expect` вернуть хотя бы одну диагностику с этим `code` и `pointer` (JSON Pointer). Дополнительные диагностики допустимы.

## Правила

- Один файл — одно нарушение. Имя файла описывает нарушение в kebab-case.
- Новое требование уровня L1 добавляется вместе с фикстурами в обе папки.
