# История и отмена правок Studio

Пакет после PR #40. История относится ко всему Change Set, включая другие
страницы. Отмена/повтор меняют только его рабочие версии через публичный
Command API; head и публикации не меняются.

| ID | Контракт |
|---|---|
| STU-050 | Панель истории показывает действия CS: автор, время, описание/вид операции, диапазон seq, отмена/повтор; загружает более ранние действия без обрезания группы. ru/en, клавиатура, состояния загрузки/ошибки/пустого списка. |
| STU-051 | Одна сохранённая пользовательская правка Studio — одна серверная группа. Отмена текста атомарно отменяет локальный контент и привязку в обратном порядке; повтор восстанавливает всё действие. |
| STU-052 | Кнопки и Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z используют undo/redo с expectedSeq и Idempotency-Key. В input/textarea/select/contenteditable работают собственные горячие клавиши поля. Во время записи/неопределённого исхода новые записи блокируются. |
| STU-053 | При успехе, отказе, конфликте или потерянном ответе перечитываются документ, seq и история; preview обновляется из авторитетного состояния. Неполученная команда не переигрывается с новым seq автоматически. Повтор после неопределённости может повторить только то же замороженное тело/ключ. |
| STU-054 | Владелец, open/state, текущие права и политики проверяются заново. Неподдерживаемая операция блокирует отмену всей группы без частичных изменений. Undo/redo добавляют новые записи со ссылками undoOf/redoOf, без удаления старых действий. |

## Серверный контракт

`apply-operations` получает необязательный `group: true`: сервер создаёт batchId
для этого атомарного пакета. По умолчанию batchId отсутствует и старые операции
отменяются по одной. Studio передаёт group для каждой явной кнопки сохранения.
undo/redo `{changesetId, expectedSeq}` отменяют/повторяют последнюю доступную
группу; старые записи без batchId считаются отдельными действиями.

Undo применяет сохранённые inverse по убыванию seq. Redo применяет inverse
записей undo по убыванию seq, восстанавливая исходный порядок. Проверки прав,
политик и валидация те же, что у обычных операций. Любой отказ откатывает всю
транзакцию. Несколько undo/redo образуют стек. Новая обычная запись очищает redo;
rebase также ставит барьер для прежнего redo. История до барьера остаётся видимой.
document.create/schema без обратной операции не получают фиктивную отмену.

`GET /api/v1/changesets/{id}/history[?beforeSeq=N]`: design.read, проект из
аутентификации, согласованный снимок в read-only repeatable-read транзакции.
Ответ `{seq, items, nextBeforeSeq, canUndo, canRedo, undoReason, redoReason}`:
20 действий от новых к старым, без разделения группы. История возвращает
метаданные и типы/цели операций, без сырых before/after/payload. Доступность
кнопок рассчитана сервером; результат записи всегда проверяется повторно.

## Приёмка и границы

PostgreSQL: несколько групп/объектов, точный текст и все локали после undo/redo,
атомарный отказ, права/владелец/state/seq, идемпотентность, очистка redo, rebase,
старые негруппированные вызовы и пагинация истории. Property-based тест проверяет
цикл правка → undo → redo. UI/API/адаптер и Chromium проверяют панель, кнопки,
горячие клавиши, поля ввода, preview, отказы и потерянный ответ.

Палитра/структура подключены в [следующем пакете](studio-structure.md).
[Review/publish UI](studio-publishing.md) подключён отдельным пакетом.
Это частичный M4. Следующие пакеты: CodeMirror/JSON diff,
production identity, SSE/presence, content editor и Agent. Произвольная отмена
выбранного старого действия и coalesce частого ввода сюда не входят.
При выборе на холсте в режиме «Дизайн» фокус возвращается выбранному элементу
дерева Studio, чтобы горячие клавиши работали после клика внутри iframe.
Режим «Взаимодействие» сохраняет фокус приложения.
Миграция 15 добавляет метаданные к существующему журналу без преобразования
старых операций; downgrade блокируется при наличии новых групп, redo-ссылок
или сохранённых барьеров повторения.
