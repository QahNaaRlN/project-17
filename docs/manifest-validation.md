# Проверка документа по manifest

Текущий серверный модуль `apps/server/internal/composition/manifestdoc` предоставляет `Validate(document, manifest, resolveComponent)`. Он проверяет готовность manifest (MF-003), его формат и семантику (MF-001), затем L1 документа и часть L3 по выбранному manifest:

- встроенные и native-типы, свойства, статические значения, `content`, обязательные входы/default;
- скалярные и вложенные типы §4, `pattern`, даты, формат ссылок, RichText v1 и ограничения блоков/меток;
- адаптивные свойства: `responsive`, обязательный `base`, объявленные breakpoint'ы;
- контейнеры, имена слотов, `min`/`max` и `allowedTypes`, включая отсутствующий слот с `min > 0`;
- события и предупреждения об устаревших типах;
- входы и слоты Composed по точной версии, которую передаёт resolver вызывающего кода.

Диагностики содержат `code`, `severity`, `pointer`, `nodeId`, `params`; ошибки блокируют результат, предупреждения не блокируют. Входные данные не изменяются. Отсутствие активного manifest даёт `MANIFEST_NOT_READY`; Composed без разрешённого компонента — `COMPONENT_NOT_FOUND`.

Источник встроенных контрактов — `packages/manifest/schema/builtin-catalogue.json`; генерация обновляет TypeScript-каталог и JSON Go. Manifest не переопределяет встроенные имена. Анализ `DocumentUses` учитывает также встроенные адаптивные свойства и токены (`Stack.direction`, `Container.size`), чтобы не пропускать затронутые документы.

Единый сервис `composition/validation` выбирает активный manifest окружения или неизменяемого кандидата связанного схемного Change Set. Composed разрешается по точной номерной версии либо по рабочей версии того же Change Set / перспективной публикации / опубликованному указателю окружения; чужие черновики недоступны. Транзитивные компоненты проверяются с обнаружением циклов, а публикация компонента повторно проверяет существующих потребителей `live`.

Этап `composition/bindingdoc` реализует серверные проверки L4 (IR-042/043/052/053):

- пути `$content`, `$local`, `$props`, `$item`, `$index`, `$each`, `$data`, `$context`; типы полей схем, входов и результатов источников данных;
- доступность `$item` и `$index` только внутри Repeat, внешние aliases через `$each`, контекст native-предков в детях и слотах; `Repeat.empty` получает внешний контекст;
- совместимость типов, обязательность и fallback, идентичность схем reference и видов asset, enum/list/object; глубина разыменования reference ограничена тремя переходами;
- встроенные и manifest-форматтеры, тип входа и буквальные аргументы; шаблонные переменные;
- параметры источников данных в ограниченных областях; пагинация предоставляет `items` и `hasMore`;
- пути и типы операндов `when`, действия manifest и встроенные действия, аргументы и цели узлов/страниц, параметры маршрута, `data.loadMore` только для пагинируемого источника; заглушки `pending` блокируют публикацию.

`apply-operations` и `undo` возвращают необязательное поле `warnings[environment][documentId]` с предупреждениями L4, сохраняя незавершённый черновик. Выбираются сохранённые targets Change Set, иначе окружения проекта; для схемного Change Set — окружение кандидата. До появления manifest/кандидата предупреждения не вычисляются. Ошибки БД откатывают команду. Подача на проверку сохраняет блокирующие ошибки в checks и переводит Change Set в `failed`; согласование повторно проверяет контракт перед записью решения. Публикация и продвижение проверяют перспективное состояние до записи версий, указателей, маршрутов и outbox. Анализ влияния использует тот же сервис для head, опубликованных и рабочих версий.

Остаются: остальные проверки L2 (существование/публикация сущностей и assets), design/policy/A11Y (L5–L7), автоматическая регистрация/активация manifest и совместная схемная публикация. Значения динамических URL проверяет будущий runtime; сервер проверяет их статические контракты. TypeScript сейчас имеет общий каталог и эквивалентную валидацию `pattern` в manifest; серверные L3/L4 реализованы в Go.

Проверки: общие Go/TS фикстуры для `pattern`, эталоны полных диагностик manifest, тесты контрактов документов, случайные данные и fuzz. Пороги покрытия из `docs/testing.md` сохранены.
