## 1. Результат и границы

Редактор выбирает событие узла, настраивает последовательность действий
и их аргументы формами, задаёт условие показа блока и проверяет результат
в настоящем приложении. В карточке Repeat аргументы берутся из соответствующего
элемента; редактируется один шаблон. Сохранение, отмена, конфликт, согласование
и публикация используют существующий Change Set.

Приёмочный путь: Collection → источник → Repeat → кнопка «В избранное»
с `store.favorite($item.id, $item.title)` → условие карточки по полю элемента
→ проверка design/interact и RU/EN → согласование вторым человеком → публикация
→ действие и условие в новом публичном браузере. ID, JSON и выражения для этого
пути вручную не вводятся. Обработчик заранее зарегистрирован кодом приложения.

В пакет входят страницы, события builtin/native из действующего контракта,
зарегистрированные действия, цепочки 1…8, прямые типизированные аргументы,
`navigate` к URL/anchor и `scrollTo` с выбором цели, конструктор `when`.
Условия используют `exists`, `empty`, `eq`, `neq`, числовые сравнения,
`in`, `and`, `or`, `not` в пределах ниже.

Не входят event payload/`$event`, Form/Input и состояние формы, создание кода
обработчиков, произвольные HTTP/JS, платежи или оформление заказа,
конструктор `data.loadMore`, Modal, track/аналитика, page navigation с route
resolver, изменение `provides`, редактор `$props`/`$each`/`$index`, component.extract,
Missing Capability/context pack, новые вложенные Repeat, advanced bindings,
общий кэш loader, Figma и production. M4 и полный шаг 4 MVP остаются частичными.
M5 развивается отдельным пакетом Missing Capability после своей спецификации.

В [StudioReview](../apps/server/internal/workflow/studio.go) `canEdit` сейчас
требует content.write либо design.compose. Пользователь с design.read и
behavior.use не получает самостоятельного пути правки события своего CS.
Добавить отдельные `canEditBehavior` и `canEditCondition`; прежний `canEdit`
сохранить для совместимости. Нельзя просто включить все формы свойств при
наличии behavior.use. Команды остаются источником решения о доступе.

Два расхождения нельзя скрывать UI-проверкой: аргументы событий в Go используют
общую совместимость с преобразованиями, а runtime проверяет фактический тип;
Go также разрешает упорядоченные date/datetime, тогда как evaluatePredicate
сравнивает только конечные числа. Для новых прямых аргументов нужна строгая
совместимость. В конструкторе v1 упорядоченные сравнения доступны только number;
существующие сравнения дат сохраняются для чтения с пояснением ограничения.
Поддержка сортируемых дат требует отдельного согласования Go/TS и не объявляется
реализованной этим пакетом.

## 4. Контракты записи и права

Новые типы операций и миграция БД не нужны. Формы и серверные дополнения
используют существующие операции.

```json
{
  "type": "node.setBehavior",
  "target": "<page object id>",
  "payload": {
    "nodeId": "n_favorite",
    "event": "click",
    "handlers": [
      { "action": "store.favorite", "args": { "id": "$item.id", "title": "$item.title" } }
    ]
  }
}
```

```json
{
  "type": "node.setCondition",
  "target": "<page object id>",
  "payload": {
    "nodeId": "n_card",
    "when": { "op": "eq", "args": ["$item.category", { "lit": "Керамика" }] }
  }
}
```

События нормализуются в массив только при сохранении редактируемого события.
Удаление последнего события удаляет пустой on; удаление when удаляет поле IR.
Соседние события, неизвестные поля сохранённого ActionCall и чужие complex
operands не пересобираются из упрощённой модели. Редактируемая цепочка с
неподдержанным аргументом читается целиком; явная замена не маскируется
пустой/default формой. Отдельные сохранения on и when — отдельные undo-жесты.

`canEditBehavior = own && open && standard && behavior.use`,
`canEditCondition = own && open && standard && design.compose`.
Добавить эти advisory-поля в StudioReview, Query/BFF и frontend types, сохранив
прежний canEdit. Отсутствующее новое поле у несовместимого сервера не разрешает
запись. Контракт полей зафиксировать в описании Query API и синхронизировать
Go/BFF/frontend types; штатная генерация затронутых контрактов входит в проверки.
Управление историей, открытие работы и навигация не должны ошибочно требовать
design.compose для behavior-only редактора; остальные формы остаются закрыты
без своего права. Наличие флага не заменяет проверку Command Bus.

В changes/workflow расширить существующий content gate на on/when с primary
content, в том числе при удалении и undo/rebase; повторно проверять права
автора перед согласованием/публикацией. Сам handler остаётся авторизованным
кодом приложения: behavior.use разрешает декларацию, не выдаёт пользователю
произвольный доступ к сервисам приложения.
Delivery уже сканирует on/when для проекции primary content; закрепить точную
локаль и обновление ETag тестами без введения нового resolver или loader endpoint.

Планируемое уточнение locked: сейчас [IR](spec/02-ir.md#3-узел) и
[CheckEdit](../apps/server/internal/composition/policydoc/policy.go) защищают
структурные поля, но не изменения on/when. В этом пакете к защищённым изменениям
отнести on/when locked-узла и его поддерева, а также when на предке, меняющий
видимость locked-поддерева. Проверить оба снимка группы, чтобы снятие lock,
перемещение и последующая правка не обходили правило. Требуется
design.zones.manage; это уточнение надо отразить в архитектурной документации
при реализации. Политику обычного контента/props в locked здесь не расширять.

## 5. Формы аргументов и условий

Источники аргументов: `$content` из схемы страницы, существующий `$local` text,
`$data` из result-контрактов, `$item` ближайшего Repeat и object-поля этих областей;
`$context.locale`, `$context.route.path`, объявленные route params,
`$context.viewer.authenticated` и native provides ближайших предков.
Runtime приложения должен действительно передавать выбранные поддержанные
context-поля. Само наличие пути в IR не создаёт viewer/route/provides в приложении;
отсутствующее runtime-значение показывает диагностику. Viewer condition не
является авторизацией данных или серверной операции.

Пути выводятся по контракту до глубины 8, до 200 записей с сообщением о пределе.
Индексы списка и разыменование reference не создаются. Empty не получает item
своего Repeat; внешний item у legacy вложенности сохраняет действующий scope.
Прямые object/list arguments допускаются при строгой структурной совместимости,
но ручной JSON-редактор литералов вместо формы не вводится. Required тип без
поддержанного literal/path делает новое действие недоступным с объяснением.
Optional/default аргументы можно не задавать; null доступен только nullable.
Для строк использовать Unicode-ограничения и безопасные pattern manifest.
Неверный ввод остаётся виден, сохранение блокируется, прежнее значение не
становится незаметным отправляемым «правильным» значением.

Расширить анализ зависимостей предыдущего пакета на редактируемые direct args
и when: совместимая смена источника не требует удаления корректного поведения.
При несовместимости показать пути и предложить отмену либо явное снятие
затронутого события/всего when одной атомарной группой со сменой источника.
Не удалять части сложного предиката автоматически. Зависимости в неподдержанных
scopes/выражениях блокируют смену с указанием pointer до отдельной правки.

Для встроенных действий не выдумывать контракты по именам. Согласовать
используемое подмножество с Go и runtime через общий fixture/каталог:
`navigate.args.to` — Link; `scrollTo.args.target` — nodeRef.
URL вводится полем с действующей проверкой схем; anchor/target выбираются
по дереву, включая условно скрытые узлы с предупреждением. URL-строка не
превращается в Link сама: форма создаёт `{kind: "url", url: ...}`.
Для повторений цель получает prefix текущего экземпляра; действие одной
карточки не затрагивает одноимённый узел другой карточки. Page links,
Modal, track и loadMore из старого IR видны для чтения с причиной ограничения.

В when `exists`/`empty` принимают путь, а не произвольный literal. Eq/neq
и in в новой форме ограничить scalar string/text/enum/number/boolean/date/datetime;
null выбирать отдельно для eq/neq. Нельзя сравнивать целые objects/assets/links
по ссылочной идентичности JS. Для ordered comparisons только number с number;
`in` — литералы одного совместимого типа. And/or/not строятся деревом с явными
добавлением, удалением и перемещением; убрать последнее правило группы можно
только удалением группы либо снятием when, не сохранением пустого and/or.
Большие и неподдержанные существующие предикаты не обрезать до 64 узлов.

Dirty guard сохраняет данные формы при серверном отказе, seq-конфликте и
неопределённом результате. При повторе сначала разрешить неизвестный исход
существующей команды, не создавать новый жест. Reload/смена manifest не должны
размонтировать грязную форму с потерей ввода; сохранить её контекст либо явно
предложить сброс/перечитывание. Ни отмена, ни снятие прав не заставляют делать
запись для выхода из формы. Не переключать локаль поверх несохранённых literals.

## 6. Runtime, preview и публикация

Args вычисляются при подготовке plan из актуального scope. Event payload сейчас
не передаётся; значение поля ввода, DOM event или результат предыдущего действия
не выдаются за поддержанный operand. Цепочка последовательна, без параллельного
исполнения и передачи return value. Ошибка первого шага останавливает остальные;
автоматического повторения эффекта после reload/ошибки нет.

В design события выбирают узел и не запускают действия, в том числе Enter/Space
и native events. Interact — явный выбор пользователя. На время смены контекста
или обновления plan старые обработчики недоступны; при неуспешном reload можно
показывать последний снимок с признаком устаревания, но не исполнять его цепочки.
После успешного обновления используются новые locale/item/data, без накопления
обработчиков. Отмена запроса, смена страницы/CS и dispose исключают поздний commit.

Если путь when зависит от результата с SourceError, скрыть зависимый узел,
выдать безопасную диагностику и сохранить независимые разделы. Не вычислять
empty/exists по контейнеру ошибки как по обычному результату и не подменять
сбой на `[]`. Это отдельный guard подготовки plan; обычная семантика
missing/null в evaluatePredicate остаётся прежней. Легитимное поле `error`
в успешном result не считается ошибкой загрузчика. Для args из SourceError
обработчик не исполняется. Ошибка планирования/handler не должна превращать
весь React-store в 503; текущий allowlist диагностик приложения требует доработки.
Не раскрывать значения args, исходные исключения или приватный ответ loader
в диагностике/HTML/postMessage. Разрешены стабильный code, node, instance/action.

Отсутствие when и значение true дают обычный рендер; false скрывает узел.
Дерево Studio сохраняет все узлы; для скрытого узла объяснить отсутствие рамки
и дать изменить условие. Не добавлять в опубликованный IR force-visible флаг.
После снятия условия рамки и выбор восстанавливаются штатным preview-протоколом.

Публикация использует manifest и schema целевого окружения, не последний runtime
ответ и не каталог чужого CS. Проверять событие выбранного типа, action/args,
paths, ближайший item scope, Link/nodeRef цели и политики, включая отзыв прав.
Несовместимый manifest блокирует решение; существующие сложные выражения
не считаются поддержанными только потому, что UI умеет их показать.
Handler не вызывается в транзакции CMS. Preview читает working своего CS;
публичное приложение — опубликованный снимок окружения. Локаль, подпись
изображения и данные другого CS не смешиваются при обновлении.

## 7. Проверки и критерии готовности

Каждое STU-237…254 получает тест/fixture с ID по [правилам](testing.md).

| Уровень           | Обязательные сценарии                                                                                                                                                                                                                                                      |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Go / PostgreSQL   | on/when add/replace/remove/inverse, отдельные события и rebase, атомарная цепочка, seq/retry, undo/redo; behavior-only против design-only; закрытый/чужой CS, отзыв прав авторов и conditional content.read; locked до/после группы; target manifest при подаче/публикации |
| Go/TS conformance | strict args без coercion, событие/действие/цель, nullable/default и ограничения, item/empty/native context; канонические JSON операции; типы и пределы предикатов; missing/null/false/0/empty; numeric ordered vs legacy date                                              |
| Studio            | каталог без действий/событий, неподдержанные args и сохранение legacy, 8/9 шагов, клавиатурный reorder, грязная форма/конфликт/точный повтор/отзыв доступа, скрытый узел, 16/17 условий и 64/65 узлов, RU/EN и 375 px                                                      |
| Runtime / React   | design без эффектов, interact и native события, два экземпляра Repeat с разными args/DOM targets, ошибка и остановка цепочки, source failure в args/when без потери соседнего блока, устаревшая локаль/поздний ответ, отсутствие дублированных handlers                    |
| Настоящий браузер | весь STU-254 на CMS/PostgreSQL/OIDC/React, UI-создание on/when, публичная новая сессия, отсутствие draft до публикации, настоящий эффект обработчика и условное отображение                                                                                                |

Для STU-254 подготовка manifest/ролей/схем и статической раскладки через API
допустима. Событие, цепочка, аргументы, условие и его группы создаются формами
Studio. Использовать source/Repeat из предыдущего пакета, но не предзаполненный
on/when. У двух карточек проверить различные id/title и условие category;
для RU/EN задать различающиеся входные данные, чтобы одинаковая картинка не
маскировала устаревший plan. Design click/Enter дают ноль вызовов handler,
interact воздействует на нужную карточку; безопасный fixture handler позволяет
проверить порядок двух шагов и отказ первого без внешних побочных эффектов.
Для navigate/scrollTo проверить реальную anchor-цель в Repeat и клавиатуру.

Отдельные API-тесты подтверждают, что actor с behavior.use без design.compose
меняет on своего CS, не меняет when/design; actor с design.compose без
behavior.use не меняет on. Не подменять права всеобъемлющей admin-ролью.
Другой OIDC-пользователь согласует/публикует; автору самосогласование запрещено.
До публикации новая публичная сессия не видит draft on/when; после публикации
поведение и условия работают без preview attributes. Проверить запрет публикации
неизвестного action/неверного scope, конфликт и один потерянный ответ после commit.
Отчёт фиксирует исходный SHA/dirty, manifest hash, CS/page версии и результаты
без credentials и приватных args.

Порядок реализации: conformance и серверные права/проверки → typed args/events
и сохранение → predicate builder/hidden selection → preview/runtime guard →
двухпользовательская приёмка. Перед PR: генерация затронутых контрактов, Go build,
целевые тесты, pnpm check и зелёный CI конечного SHA с Linux race/coverage и
браузерными сценариями. Пороги не снижать; ограниченные проверки явно отмечать.

## 8. Статус, зависимости и дальнейшая очередь

STU-237…254 реализованы в отдельной ветке после PR #58. Настоящая локальная
приёмка и результаты проверок зафиксированы в [отчёте](studio-behavior-conditions-evidence.md).
До слияния пакет не считается доступным в dev.

Зависимости: действующий manifest с events/actions/args и соответствующий registry
клиентского приложения; готовые page/content/data/Repeat, существующие операции,
preview bridge и CS workflow. Для приёмки нужны два OIDC-пользователя, PostgreSQL,
управляемые локальные handlers и различающиеся locale/item данные. Docker/IdP
нужны для выполнения приёмки, не для написания этой спецификации.

После пакета остаются component.extract/Composed authoring, advanced expressions,
редакторы остальных builtin, payload/формы, Missing Capability и измерения NFR.
Их порядок перепроверяется по фактическому dev; полный M4, M5 и эксперимент
не объявляются завершёнными.
