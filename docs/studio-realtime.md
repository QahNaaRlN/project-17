# Studio: обновления и присутствие

Пакет STU-110…114 реализует SSE-инвалидацию и CHG-042/STU-025.

| ID | Контракт |
|---|---|
| STU-110 | Аутентифицированный `GET /api/v1/events?environment=…&documentId=…&changesetId=…` возвращает SSE. Проект определяется сессией/токеном, документ и CS проверяются в этом проекте и окружении. |
| STU-111 | Каждая новая успешная изменяющая команда повышает ревизию проекта в той же транзакции. Отказ, rollback и идемпотентный повтор её не повышают. SSE передаёт только ревизию, без содержимого документов/команд. |
| STU-112 | `id` — строковая ревизия; `after` или Last-Event-ID позволяют обнаружить пропуск после reconnect. Пропуски объединяются в одну инвалидацию. Первое подключение также перечитывает состояние. Соединение ограничено 25 секундами: новая аутентификация проверяет отзыв сессии/токена и права. |
| STU-113 | `presence-heartbeat`/`presence-leave` проходят через Command Bus, CSRF и права design.read. Lease отдельный для вкладки, TTL 30 секунд, heartbeat каждые 10 секунд. Сервер проверяет документ/CS/окружение. Presence — только информация, без блокировок/права редактирования чужого CS. |
| STU-114 | Studio обновляет каталоги, историю, проверки, документ и preview. Несохранённые формы и неизвестный исход записи откладывают перечитывание; показывается уведомление. Переключение документа и выход отменяют поток, таймеры и heartbeat. |

События `invalidate` и `sync` содержат `{revision: string}`; `presence` содержит
`{items: [{actorId, actorName, changesetId, changesetTitle}]}` для текущего документа
и окружения. Вкладки одного актора в одном CS объединяются. Снимок presence
обновляется при подключении и каждые 10 секунд; истёкшие lease не выдаются.
После сетевой ошибки клиент очищает устаревший список и повторяет подключение
с задержкой, ограниченной 10 секундами. Медленный читатель имеет ограниченное
время записи; stream не удерживает соединение PostgreSQL между опросами.

Для этого MVP общие ревизии и ephemeral lease находятся в PostgreSQL:
это обеспечивает работу нескольких экземпляров CMS без дополнительной зависимости.
Redis presence из целевой архитектуры остаётся оптимизацией; Yjs/совместное
редактирование одного CS и измерение NFR не входят в пакет. Ревизия занимает
одну строку на проект; просроченные lease очищаются при heartbeat.

Далее — отдельный пакет Agent; конструкторы данных/поведения, advanced bindings,
component.extract, буфер/wrap и полная приёмка M4 остаются в плане.
