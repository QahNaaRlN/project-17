# Запросы недостающих компонентов: реализация и проверка

Дата: 2026-10-20. Ветка: `feature/capability-component` от `dev` `9dbdaf0`.
[Спецификация STU-355…374](studio-capability-component.md) одобрена пользователем
2026-10-20 вместе с решениями §11. Пакет не слит; полный M5 не завершён.

## Реализовано

- IR: необязательное поле `pending` узла (схема IR 1.0, Go/TS-валидаторы,
  conformance-фикстуры); заглушка без `on`/`ref`, не у `Composed`.
- Проверки: заглушка живого запроса вида `component` проверяется по предложенному
  контракту (props, container, slots) как компонент manifest; каждая заглушка —
  ошибка публикации `COMPONENT_PENDING_CAPABILITY`; неизвестный, черновой,
  отменённый или вложенный — `CAPABILITY_PENDING_INVALID`; вне CODE —
  `POLICY_PENDING_REQUIRES_CODE`.
- Операции: `node.clearPending` (обратная `node.setPending` — только журнал);
  конвейер отклоняет заглушку без живой привязки (копию, вставку агентом),
  снятие метки до выполнения и `component.extract` поддерева с заглушкой.
- Миграция 00025: вид запроса `component`, место вставки и начальные свойства,
  вид привязки `node`, состояние `invalid_props`.
- Команды: создание с контрактом и местом, отправка со вставкой заглушки,
  «Вставить ещё экземпляр» (`attach-capability-request` с местом), отсоединение
  через удаление узла, ручной resolve «Применить доступный компонент».
- Context pack: место вставки, начальные свойства, до 5 похожих компонентов
  manifest с записями индекса кода.
- Выполнение: условия STU-339 для компонента, совместимость STU-368, снятие
  метки системой `cms-system` одной группой по CS, `invalid_props`, undo/повтор;
  preview/<ref> рендерит настоящий компонент только в ответе.
- Рендер: runtime/React показывают заглушку нейтральным блоком
  `data-cms-pending` только в preview, код приложения не вызывается.
- Агент: `report_missing_capability` создаёт draft вида `component`.
- Studio: мастер «Нужен другой компонент…», бейдж заглушки в Structure и
  панели, свойства заглушки по контракту, карточка запроса вида `component`.
- Витрина: компонент `PromoBanner` (его «реализует разработчик» в приёмке);
  базовая сборка приёмки его вырезает.

## Отступления и уточнения при реализации

| Тема | Решение | Основание |
|---|---|---|
| Ключ уже есть в manifest/builtin | `CAPABILITY_ALREADY_AVAILABLE`, как у действий; `CAPABILITY_KEY_TAKEN` — только открытый запрос | Единые коды Studio для обоих видов |
| Слоты заглушки | Слоты допустимы в контракте и IR, но runtime их не рендерит (`CMS_SLOT_UNSUPPORTED`, как у native) | Native-слоты в runtime пока не поддержаны; в приёмке используются вложенные блоки (`container`) |
| Место вставки в слот | Только в слот без `allowedTypes` | Ключ запроса не может быть в списке допустимых типов |
| Название в блоке заглушки | Показывается имя компонента, не заголовок запроса | Runtime не читает запросы; заголовок виден в Studio |
| Права `cms-system` | Добавлено `design.compose` (и на стадии проверки прав) | `node.clearPending` требует его; конвейер по-прежнему пропускает только две операции системы |
| preview/<ref> в приёмке | Проверен Go-тестом STU-367, не на стенде | Стенд не регистрирует preview-окружение PR |

## Автоматические проверки

- Go: тесты с ID требований — жизненный цикл (заглушка, блокировка публикации,
  несовместимый и совместимый компонент, потомок слияния, undo/повтор), отказы
  создания/места/свойств/контракта, операции над заглушкой, экземпляры и
  отсоединение, ручной resolve (несовместимость, неверные свойства), pack,
  preview/<ref>, узкое правило `cms-system`, проверки IR и CODE-зоны, агентский
  черновик; conformance-фикстуры IR и golden-диагностики.
- CI-эквивалент в Linux-контейнере: `go test -race` с PostgreSQL и порогом покрытия
  (`assets`/`imagedelivery` в контейнере без S3/imgproxy не запускаются; в CI запускаются)); покрытие Go 95.10% при пороге 95% (цель STU-373 ≥ 95.3% по CI не достигнута — оставшиеся пропуски в основном ветки ошибок хранилища).
- TS: рендер заглушки в runtime/React, мастер компонента, панель «Выполнение»
  компонента, ESLint, typecheck, Prettier.
