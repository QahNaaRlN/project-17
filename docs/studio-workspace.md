# Страницы и рабочие черновики

Пакет после PR #39. Studio открывает работу через список страниц, затем список
своих открытых стандартных Change Set для выбранной страницы и окружения.
Используется тот же публичный Command/Query API и серверный актор, который
владеет сохранениями. В локальном адаптере это актор настроенного service token;
универсальный OIDC-вход реализован в [отдельном пакете](studio-identity.md).

| ID | Контракт |
|---|---|
| STU-040 | Выбрать страницу по маршруту и имени корня без ввода UUID. Каталог включает head и страницы, созданные в своих открытых CS выбранного окружения; компоненты, удалённые и чужие неопубликованные страницы исключены. |
| STU-041 | Для выбранной страницы показывать только свои open/standard CS с target выбранного окружения, в которых страница читается как working либо head. Владельца определяет сервер из аутентификации. |
| STU-042 | Создать именованный стандартный CS через create-changeset с одним target текущего окружения и открыть выбранный head в нём. Страница, существующая только в CS, открывается в своём CS; новый пустой CS для неё не предлагается. |
| STU-043 | Двойной клик и повтор после неизвестного исхода создания используют один Idempotency-Key и неизменное тело. Ошибка открытия после успешного создания повторяет открытие созданного CS, не создаёт второй. |
| STU-044 | Загрузка, пустые списки, отказ, повтор чтения, пагинация и устаревший выбор доступны с клавиатуры и переведены на ru/en. Смена страницы сбрасывает выбранный CS; редактор переключается только по явному Открыть. |

## Query API

`GET /api/v1/pages?environment=staging[&after=UUID]` и
`GET /api/v1/working-drafts?environment=staging&documentId=UUID[&after=UUID]`
требуют `design.read`, ограничены проектом аутентифицированного актора и
существующим standard окружением. Ответ `{items, nextCursor}`: максимум 50,
UUID по возрастанию, `nextCursor=null` в конце. Фильтрация выполняется до LIMIT.
Неизвестные/повторные параметры и неверный курсор дают `400 PARAM_INVALID`.
Страницы возвращают `{id, path, title, hasHead}` без тела IR. Источник — глобальный
head (как у существующего чтения/редактирования), а не Delivery publication.
Для страницы без head маршрут/имя берутся из последнего своего подходящего CS.
Страницы без маршрута пока исключены: текущий preview требует маршрут.

Адаптер разрешает только эти два новых чтения и create-changeset с ровно одним
настроенным target; сохраняет Host/Origin/Fetch Metadata и credential вне браузера.
Создание CS не записывает working version до первой операции, не меняет head и
не публикует. Существующие ссылки с двумя ID сохраняются.

## Проверка и границы

Контрактные тесты PostgreSQL проверяют владельца, проект, окружение, доступность
страницы, состояния, компоненты, удаление и пагинацию. UI/API/адаптер проверяют
выбор, создание, повторы, отказ и потерянный ответ; Chromium — открытие без ID,
создание и сохранение после открытия. Пороги покрытия сохраняются.

Пакет не завершает M4. CodeMirror/JSON diff подключён в
[пакете JSON](studio-json-diff.md). Content editor подключён в [пакете контента](studio-content.md).
Остались SSE/presence и Agent. [Review/publish](studio-publishing.md), история и undo/redo теперь
реализованы в [следующем пакете](studio-history.md).
Палитра, DnD/перемещение, удаление и дублирование реализованы
в [пакете структуры](studio-structure.md).
