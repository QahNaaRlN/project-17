# Studio: история публикаций и безопасный откат

Статус: **реализовано и слито в dev в PR #54; локальная приёмка и CI пройдены**.
Дата: 2026-10-15. Основа: `dev`, commit `9bd2c83` (PR #53 слит).
Требования: STU-162…175; CHG-052, PUB-030…033.

## 1. Цель и границы

Пользователь видит историю выбранного окружения, открывает публикацию,
изучает её изменения и последствия отмены, явно подтверждает откат и проверяет
результат в приложении. Сценарий дополняет [Работы и согласование](studio-work-approval.md)
и [сравнение всего CS](studio-review-diff.md). Figma не является зависимостью:
используются существующие графитовые поверхности, фиолетовый акцент, Inter,
кнопки, диалоги и состояния Studio.

Пакет включает серверный Query API истории и сравнения публикации, защиту
команды отката актуальным снимком, Studio BFF, экран и локальную приёмку.
История включает `publish`, `promote`, `rollback`, в том числе публикации без
страниц: только сущности или ассеты. Просмотр не требует открытого CS.

Откат — отмена конкретной публикации, а не восстановление произвольной даты
или всего окружения. Возвращаются только её объекты к `previousVersionId`.
Незатронутые объекты сохраняют состояние. Цепочки автоматически не откатываются.

Вне пакета: запуск promote из Studio, schema/manifest rollback из Studio,
сравнение схем и миграции, произвольные пары исторических UUID, бинарный/визуальный
diff, редактирование исторической версии, новая политика согласования отката,
unpublish, серверный поиск «Работ», внешние IdP, production и Agent/MCP.
Существующая серверная поддержка manifest rollback сохраняется, но UI её не
активирует: карточка такой публикации объясняет границу и не предлагает откат.

## 3. Семантика сравнения и отката

В карточке два явно подписанных режима:

1. **«Что изменилось при публикации»**: previous → current исходной публикации.
   Историческое сравнение остаётся доступным, даже если публикация перекрыта.
2. **«Что изменится при откате»**: фактически опубликовано сейчас → previous
   исходной публикации. Доступно к подтверждению только если все затронутые
   published pointers ещё равны current исходной публикации.

Для перекрытой публикации исторический diff не подменяется предпросмотром
исполняемого отката. Показываются блокирующие объекты и понятная причина;
автоматической отмены более поздних публикаций нет. Несвязанные более поздние
публикации сами по себе не блокируют действие: решает состояние затронутых объектов.

Пример: публикация P2 переключила страницу v1 → v2. Отмена P2 вернёт v1;
если сейчас опубликована v3, P2 перекрыта. Сначала пользователь отдельно изучает
и отменяет соответствующую более позднюю публикацию. Отмена первой публикации
возвращает отсутствие published pointer, а не пустой документ.

`null` versionId, tombstone и живая версия различимы. Удаление, восстановление,
снятие первой публикации и смена маршрута показаны явно. Для объектов без живой
версии нельзя предлагать открыть рабочий редактор. Метаданные tombstone не теряются.

**В Studio всегда `resetHead=false`.** Диалог объясняет: меняется опубликованное
состояние выбранного окружения, head и открытые рабочие версии сохраняются.
Переключатель resetHead в этот пакет не входит. Legacy API сохраняет прежний
default для совместимости; BFF требует явное false для нового UI-сценария.
Откат не отменяет одобрение CS, не возвращает merged CS в open и не меняет его seq.
Опубликованная база сравнения открытых работ становится неактуальной, поэтому
сравнение перед последующим решением перечитывается; черновик не перезаписывается.

Без согласования выполняется существующий аварийный путь с `content.publish`.
Для Studio необходимы права чтения всех затронутых видов и явная непустая причина
отката (после trim 1…2000 символов). Она передаётся в существующем command envelope
`reason`, сохраняется в publication и аудите, показывается как обычный текст.

## 5. Query API и границы доступа

Маршруты CMS ниже реализованы в этом пакете:

```text
GET /api/v1/publication-history?environment=<name>&limit=50&cursor=<opaque>
GET /api/v1/publication-history/{id}
GET /api/v1/publication-history/{id}/diff?objectId=<id>&limit=100&cursor=<opaque>
GET /api/v1/publication-history/{id}/rollback-preview
GET /api/v1/publication-history/{id}/rollback-preview/diff?objectId=<id>&snapshot=<hash>&limit=100&cursor=<opaque>
```

История: environment обязателен, limit 1…100 (default 50). Keyset-курсор
контекстно подписан и связан с проектом, актором, окружением и параметрами;
новая запись не сдвигает границу уже прочитанных страниц. Ответ содержит
`items`, `nextCursor`, без выдуманного total. Список не загружает тела и полные
item-массивы: запись содержит безопасную сводку и число объектов.

Карточка содержит publication, безопасный индекс объектов, их previous/current,
исторические подписи, summary diff, availableActions и причины недоступности.
Preview содержит publicationId, environment, resetHead=false, snapshot,
`canRollback`, blockers, индекс последствий и результат проверки зависимостей.
Отказ права исполнения не запрещает разрешённое чтение, но canRollback=false.
Manifest-changing карточка возвращает лишь manifest ID/признак изменения,
без schema-body или ложного контентного preview.

Для document/component требуется design.read, для entity/asset — content.read.
Метаданные истории доступны человеку с хотя бы одним из этих прав; для каждой
публикации требуется чтение всех её затронутых видов. Если страница содержит
публикацию с недоступным видом, весь ответ страницы отклоняется FORBIDDEN,
без частичного списка, названий, счётчиков и подмены «изменений нет».
Карточка и детали повторяют эту проверку. Не найденное в проекте — NOT_FOUND.
Legacy `/publications` и `/publications/{id}` получают такие же guards, чтобы
нельзя было обойти защиту новым UI через прежние маршруты; формы их успешных
ответов сохраняются. Права администратора не выводятся из знания UUID.

Индекс: максимум 1000 объектов и 4 MiB безопасного ответа. Детали: максимум
100 записей diff на страницу и 4 MiB. Превышение даёт явную ошибку лимита,
никогда усечённый «полный» результат; подтверждение недоступно. Курсор деталей
связан с проектом/актором/publication/object/mode/snapshot. Неизвестные параметры,
неверный limit/UUID/курсор — INVALID_ARGUMENT. Детали не принимают from/to UUID.

Безопасная проекция ассетов повторяет PR #53: не возвращаются storage keys,
credentials, signed URL или бинарное содержимое. Известный fileHash и безопасные
характеристики файла видны; смена файла подписана «Файл изменён».
Метаданные авторов не включают email/OIDC claims: безопасное имя или actorId.

## 6. Снимок и защита команды

Query выполняется в read-only REPEATABLE READ транзакции. Preview вычисляет
гипотетическое состояние без записи pointers, маршрутов, CS или outbox.
Используется общий механизм проверки publication с виртуальной подстановкой
previous-версий; нельзя применять «пробный rollback» и потом откатывать его
побочные эффекты. Отказ dependency/route/manifest validation виден как blocker.

Snapshot — SHA-256 канонического представления: project/actor/права,
publication ID и неизменяемые пары items, выбранное environment и resetHead,
активный manifest и контракт окружения, настройки проекта/политик,
все published pointers (включая ID последней переместившей их публикации)
и маршруты этого окружения, используемые при проверке. Происхождение pointer
защищает и от перехода к другой версии с последующим возвратом к прежней.
Исторические committed тела привязаны к версии и canonical hash; порядок ключей
и строк не меняет снимок. Head не включается как основание отмены при false.
Включение всех pointers консервативно инвалидирует preview и при несвязанной
публикации; после перечитывания откат снова возможен, если его условия соблюдены.

Расширяется существующая команда:

```json
{
  "reason": "Возвращаем прежний текст и маршрут после проверки",
  "payload": {
    "publicationId": "<uuid>",
    "resetHead": false,
    "expectedRollbackSnapshot": "<sha256>"
  }
}
```

Передача — через Command Bus с Idempotency-Key, обычным envelope/аудитом и OIDC.
Новая Studio/BFF требует snapshot, false и непустую причину. Для прежних
API-клиентов поле snapshot необязательно; существующие атомарные проверки
rollback сохраняются, но такой клиент не получает гарантию просмотренного diff.
При переданном snapshot сервер также требует false и допустимую причину,
повторяет права чтения/исполнения и запрещает manifest-changing UI-путь.

Порядок: Command Bus проверяет актора и точный успешный idempotent replay;
handler получает проектные/окруженческие и объектные блокировки в общем порядке,
сверяет snapshot, published pointers, тип/причину, проверяет будущие зависимости,
выполняет существующую транзакцию и сохраняет результат. Важно: replay уже
успешной команды возвращает прежний rollback, несмотря на то, что её выполнение
изменило снимок; новая команда по старому снимку отклоняется.

Новые коды: `ROLLBACK_SNAPSHOT_STALE` (409), `ROLLBACK_UI_UNSUPPORTED` (409),
`PUBLICATION_HISTORY_LIMIT` (413). Сохраняются FORBIDDEN/POLICY_DENIED,
NOT_FOUND, ROLLBACK_SUPERSEDED, VALIDATION_FAILED, IDEMPOTENCY_KEY_REUSED.
Stale/superseded закрывает диалог, оставляет понятную причину и предлагает
перечитать preview. После известного отказа новый snapshot и новое подтверждение
создают новый ключ. Неизвестный исход не считается отказом; нельзя генерировать
новый ключ после timeout. Повтор гарантирован в пределах существующего срока
хранения idempotency: после его истечения UI требует сначала установить результат
по истории/источнику и не повторяет команду автоматически.

После успеха UI перечитывает историю, открывает новую rollback publication,
обновляет preview/сравнение затронутых работ и показывает ссылку на опубликованную
страницу, если она осталась доступна. Ответ команды не доказывает выполнение
CDN-вебхука: UI сообщает об отмене публикации, не обещая уже очищенный внешний кэш.

## 7. Экран и подтверждение

Список: «Публикации», окружение, строки с временем/автором/видом/объектами;
rollback имеет подпись «Откат» и ссылку на исходную публикацию, promote — «Перенос».
Отсутствующий автор/CS не ломает список; неизвестные данные подписаны явно.
Карточка открывается отдельно, поддерживает ссылку/возврат без потери страниц списка.

Пользователь выбирает «Посмотреть последствия отката». Сначала загружается
preview, затем доступно «Отменить публикацию…». Диалог содержит окружение,
дату/автора исходной публикации, число и виды объектов, восстановленные/снятые
маршруты, предупреждение о сохранении черновиков, поле причины и действие
«Подтвердить откат». Действие disabled при блокерах, загрузке, незаполненной
причине, неполном preview или неизвестном исходе предыдущей команды.
Клавиатура/Escape/закрытие не запускают команду. Пока отправка идёт, повторный
клик и смена выбора запрещены. При dirty редакторе действует общий guard.

## 8. Приёмка и доказательства

| Проверка                   | Обязательный результат                                                                                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| История >100 публикаций    | Все доступны страницами; совпадающее время, вставка новой публикации и повтор страницы не дают дублей/пропусков старого набора. Список без страниц/entity-only/asset-only работает.                    |
| Исторический diff          | Более поздняя публикация не меняет previous/current; отсутствующее поле/null/0/false, точные числа, локали, RichText, движение узла, metadata/file replacement и tombstone не теряются.                |
| Обычный откат              | Две публикации одной страницы: preview v2 → v1, явная причина, новая rollback запись, прежний текст/маршрут в Delivery API и приложении. Число версий и CS не увеличилось; head/working/seq сохранены. |
| Первая публикация/удаление | Отмена первой публикации снимает pointer/маршрут; отмена удаления восстанавливает прежнюю живую версию. Обратный результат отражён в истории.                                                          |
| Смешанный набор            | Документ, компонент, сущность и asset metadata возвращаются вместе; незатронутые объекты/другое окружение сохраняются. Проверены live-потребители и ссылки.                                            |
| Перекрытие                 | Изменение хотя бы одного item блокирует весь откат; независимая публикация требует свежего preview, но затем не запрещает отмену. Конфликт возвращаемого маршрута блокирует всё.                       |
| Гонки                      | После preview второй пользователь публикует, меняет manifest/права/политику или зависимый pointer: старый снимок не исполняется, даже без SSE. Одновременные команды не дают частичного состояния.     |
| Ошибка записи/валидации    | Pointers, маршруты, audit/publications/outbox и версии имеют прежние значения; нет успешного UI-статуса.                                                                                               |
| Доступ и секреты           | Другой проект/версия/актор/курсор, отсутствие чтения одного вида, отзыв сессии и cached UI не раскрывают тела/метаданные. Legacy маршруты не обходят guards. Агент не получает новый аварийный путь.   |
| Ограничения                | Manifest-changing, unknown kind, >1000 объектов и >4 MiB дают явную недоступность; отсутствующий/сломанный следующий ответ не выглядит полным сравнением.                                              |
| Идемпотентность            | Потеря успешного ответа и точный повтор создают один rollback/один набор outbox; другой payload с тем же ключом отклонён. Истечение срока не вызывает автоматического повтора.                         |
| UI                         | RU/EN, 375 px, клавиатура/фокус, loading/error/empty, stale, поздний ответ, dirty и unknown outcome проверены.                                                                                         |

Автоматизация: Go integration/race для транзакций/guards/queries; тесты Studio
для состояния и подтверждения; Playwright для сквозного сценария. Реальная
локальная приёмка использует новый тестовый проект/БД и двух OIDC-пользователей:
автор создаёт и подаёт две версии, другой человек согласует, выполняется явная
публикация, затем просмотр/откат через UI. Проверяется сохранённый открытый
черновик и новый текст/маршрут в React-store, а не только toast или mocked API.
CDN outbox проверяется в БД; реальная доставка внешнему CDN не заявляется.

## 9. Порядок реализации и готовность

1. Сервер: bounded history queries, права старых/новых маршрутов, исторический
   diff, read-only rollback preview и общий snapshot/guard с транзакцией.
2. Studio/BFF: раздел, карточка, сравнение, причина/подтверждение, idempotent
   recovery, invalidation и защита редактора.
3. Интеграционная и браузерная приёмка, реальный локальный стенд, обновление
   документации с отдельными статусами «реализовано», «не входит», «зависимости».

Работа ведётся отдельной веткой от dev, PR обратно в dev. Проверки: генерация
sqlc при изменении SQL, Go build/vet/race и принятые пороги покрытия, целевые
Studio tests, полный `pnpm check`, браузерная приёмка и CI точного SHA.
До наблюдаемого успеха CI и локальной приёмки статус спецификации не меняется
на «готово». Для текущего docs-only изменения достаточны форматирование,
проверка ссылок/ID и `git diff --check`; исполнение продуктовых тестов не является
доказательством реализации ещё отсутствующего пакета.

## 10. Реализовано и локальная приёмка

Реализованы STU-162…175: keyset history, карточка/исторический diff,
read-only preview с виртуальными версиями и проверкой будущего окружения,
guarded rollback, legacy read guards, Studio/BFF и подтверждение с причиной.
Правила назначения/отзыва ролей используют те же блокировки окружений, что и
guarded rollback; сервер повторно сужает права текущими назначениями, сохраняя
ограничения исходного токена. Snapshot учитывает происхождение published pointers,
поэтому переход к другой версии с возвратом к прежней не разрешает старое решение.
При неизвестном результате UI позволяет перечитать историю без отправки команды;
после 24 часов безопасный автоматический повтор не предлагается.

Локальный стенд 2026-10-15: CMS 18133, Studio 18134, подписанный OIDC 18135,
React-store 18136, отдельная PostgreSQL database. Alice создаёт и подаёт работу,
Bob согласует и явно публикует её через Studio; затем открывает историю, смотрит
последствия и подтверждает откат документа и сущности. Проверены прежняя
published версия, сохранность head и открытого CS, восстановление статьи через
Delivery API и опубликованного текста в чистой браузерной сессии.
Сессия опубликованной витрины отделена от Studio preview cookie: предпросмотр
сохранённого черновика вправе продолжать показывать рабочую версию.
Мобильная ширина 375 px проверена без горизонтального переполнения.

Воспроизведение на новом стенде по [инструкции запуска](studio-work-approval.md):
собрать CMS/Studio/store, запустить `scripts/studio-review-stand.mjs` с новой
мигрированной БД и каталогом, затем последовательно выполнить
`scripts/studio-live-review.mjs` и `scripts/studio-live-publications.mjs`.
Оба используют `STUDIO_REVIEW_ADMIN_FILE` и `STUDIO_REVIEW_OUTPUT`.
Первый готовит исходный релиз с двумя людьми; второй проверяет новый пакет.
Секреты остаются в локальных private-файлах, вне Git. Непубличное доказательство:
`publication-history-acceptance.json`; снимки `publication-history-desktop.png`,
`publication-history-mobile.png`, `publication-history-rolled-back.png`.

Ограничения §1 сохранены: manifest rollback из Studio, promote UI, внешний IdP,
production и Figma не включены. Факт server commit/outbox проверен отдельно от
фактического выполнения внешнего CDN purge. Полный M4 не объявляется завершённым.
