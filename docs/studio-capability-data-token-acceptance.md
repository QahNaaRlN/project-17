# Запросы недостающих источников данных и токенов: реализация и проверка

Дата: 2026-10-21. Ветка: `feature/capability-data-token` от `dev` `870843b`.
[Спецификация STU-375…394](studio-capability-data-token.md) одобрена пользователем
2026-10-21 вместе с решениями §11. Пакет не слит; полный M5 не завершён.

## Реализовано

- IR: необязательное поле `pending` у подключения источника (схема IR 1.0,
  Go/TS-валидаторы, conformance-фикстуры); заглушка токена — строка
  `pending:<id>` в дизайн-свойстве (схему не меняет).
- Проверки: overlay предложенного контракта источника (`$data.<key>` типизирован
  предложенным результатом) и предлагаемого значения токена (без
  `DESIGN_VALUE_INVALID`); ошибки публикации `DATA_SOURCE_PENDING_CAPABILITY` и
  `TOKEN_PENDING_CAPABILITY`; неизвестная заглушка или чужая категория —
  `CAPABILITY_PENDING_INVALID`; вне CODE — `POLICY_PENDING_REQUIRES_CODE`.
- Конвейер операций: заглушка ставится только на живой привязке активного
  запроса; метка источника снимается только у выполненного; `cms-system` может
  лишь снять метку источника или записать имя токена на месте заглушки
  выполненного запроса.
- Миграция 00026: виды `dataSource` и `token`, привязки `source` и `design`.
- Команды: создание с контрактом и местом (ключ подключения и начальные
  параметры; узел, свойство и breakpoint), отправка, присоединение, отсоединение,
  ручной resolve; pack с привязками к `$data.<key>` или токенами категории.
- Runtime: заглушка источника не загружается (`CMS_SOURCE_PENDING`, пустое
  состояние); preview черновика показывает предлагаемое значение токена как
  `raw`; preview/<ref> — настоящий источник и токен.
- Выполнение: условия STU-339 и совместимость STU-389, замена группой по CS,
  `invalid_props`, undo/повтор.
- Агент: `report_missing_capability` создаёт draft видов `dataSource` и `token`.
- Studio: мастера «Нужен другой источник…» и «Нужен другой токен…», бейджи
  заглушек, карточка и раздел «Выполнение» для обоих видов.
- Витрина: источник `store.recommendations` и токен `spacing.huge`; базовая
  сборка приёмки их вырезает.

## Отступления и уточнения при реализации

| Тема | Решение | Основание |
|---|---|---|
| Совместимость источника | По форме: типы, наличие предложенных полей, элементы списка, enum, схема ссылок; границы (`min/max/maxLength`) настоящего источника проверяются на значениях страницы при замене (`invalid_props`) | Первая приёмка показала: строгое сравнение границ отвергало реализацию, добавившую разумные ограничения |
| Категории токенов в Studio | Мастер Studio предлагает токены отступов (`padding`, `gap`); сервер принимает все категории STU-375 | В Studio редактируются только эти дизайн-свойства |
| Состояния дизайна | Заглушка токена ставится в базовое значение или breakpoint; состояния (`hover` и т.п.) — нет | Мастер STU-380 не редактирует состояния |
| Привязки к результату в приёмке | Repeat по `$data.rec` добавлен командой API | Построение привязок — отдельный проверенный пакет STU-219…236 |
| Ключ уже в manifest | `CAPABILITY_ALREADY_AVAILABLE`, как у других видов | Единые коды |
