# Загрузка и обработка файлов ассетов

Пакет после PR #29: CNT-040–043, API-010/012, OPS-010. Загрузка не
меняет head, published pointers или согласованный Change Set.

1. `create-asset-upload {filename,mimeType,size,sha256}` (`asset.write`)
   создаёт сессию проекта/актора и возвращает `assetId`, pre-signed PUT URL
   на 15 минут. SHA-256 — 64 строчных hex символа исходного файла.
2. PUT идёт в уникальный staging key закрытого S3/MinIO bucket. Клиент
   никогда не получает право записи в адресуемый хэшем ключ готового файла.
3. `complete-asset-upload {assetId}` проверяет владельца/срок и атомарно
   ставит River-задачу. Повтор не ставит вторую задачу. Статус читается через
   `GET /api/v1/asset-uploads/{id}` (`asset.write`, владелец).
4. Worker проверяет фактический размер, SHA-256 и MIME по содержимому.
   Некорректный файл получает `rejected` с кодом; инфраструктурный сбой
   повторяется River. SVG проходит XML allowlist без CSS, scripts, events,
   foreignObject, внешних ссылок и DTD. Хэш готового SVG вычисляется заново
   по очищенным байтам. Исходный хэш остаётся в сессии.
5. Готовый файл явно добавляется в открытый CS через `asset.create
   {uploadId}` (без target). `asset.replaceFile {set:{fileHash}}` с target существующего
   ассета заменяет файл в рабочей версии, сохраняя метаданные. Обе операции
   используют обычные expectedSeq, журнал, проверки и публикацию. Worker
   не меняет контент. Замена поддерживает undo/rebase.

Дедупликация ограничена проектом; ready-файлы неизменяемы. Загружаемый MIME
строго сопоставляется с содержимым, лимиты: image 25 MiB, video 500 MiB,
PDF 100 MiB. Растровые изображения: размеры, PNG preview (до 320 px),
blurhash; максимум 40 миллионов пикселей перед декодированием. SVG:
очищенный файл, размеры из атрибутов при наличии. Превью SVG и извлечение
длительности/кадра видео остаются отдельными расширениями. Ни MIME из имени,
ни Content-Type объектного хранилища не считаются доказательством.

В этом пакете `/asset` по-прежнему возвращает метаданные. CDN/imgproxy
трансформации CNT-050–052 и Runtime Image требуют следующего пакета; прямой
доступ к закрытому bucket не открывается. Для новых файлов повторная проверка
готовности выполняется при публикации. Старые импортированные метаданные
без managedFile сохраняют прежний контракт.

Эксплуатация: приватный bucket создаётся оператором, staging lifecycle
удаляет префикс `uploads/` через 1 день; ready keys не удаляются этим правилом.
S3 CORS должен разрешать PUT с домена Studio. Конфигурация `CMS_S3_*`
опциональна как целое; без неё команды загрузки отвечают ASSET_STORAGE_UNAVAILABLE.

Проект может сузить список через `settings.assets.mimeTypes` (массив MIME).
Пустой массив запрещает все загрузки. Проверка повторяется worker-ом, чтобы
изменение политики во время загрузки не позволило обработать запрещённый тип.
