# Studio: очередь работ и согласование

Экран «Работы» объединяет очередь доступных страниц CS и выбранную работу:
изменённые объекты, проверки, решения согласующих, историю правок и явную
публикацию. Графитовые поверхности, фиолетовый акцент и Inter используют
существующие токены Studio; мобильная очередь показывает действие без
горизонтальной прокрутки.

| ID | Контракт |
|---|---|
| STU-144 | Очередь использует реальный work-items API и пагинацию. Поиск по названию, маршруту и имени автора, фильтры по состоянию и принадлежности применяются только к загруженным страницам работ; интерфейс явно называет этот предел. Ошибка следующей страницы сохраняет уже загруженные строки и возможность повтора. Один CS может содержать несколько страниц: ключ строки состоит из CS и documentId. |
| STU-145 | Явное открытие работы показывает её карточку в очереди и переводит фокус к заголовку. Переход в редактор отдельный. Несохранённый ввод, отправка команды и неизвестный исход блокируют смену работы. Изменение CS/seq/состояния после команды или realtime перечитывает очередь: опубликованные и недоступные работы исчезают по серверному ответу. |
| STU-146 | Карточка использует прежние review/history API и Command Bus: права, expectedSeq, комментарий запроса правок, сброс согласований, повтор потерянного ответа с тем же ключом/телом, подтверждение всего CS и окружения сохранены. Замечание текущей страницы переводит в редактор и фокусирует соответствующий узел; несохранённый ввод блокирует этот переход. |
| STU-147 | Возврат настоящего OIDC-провайдера разрешает GET-навигацию браузера к статическому `/editor` или `/` в OIDC-режиме с Fetch Mode navigate и Fetch Dest document. Это не разрешает cross-site API, команды, чужой Origin/Host или чтение произвольного пути. |
| STU-148 | Изолированный локальный стенд использует подписанный RS256 OIDC, PKCE S256, одноразовые пятиминутные коды, фиксированный loopback callback, двух различных людей, реальные серверные сессии, PostgreSQL и CMS без HTTP-подмен. Роли назначаются отдельно публичной admin-командой только в тестовом проекте; авторское согласование отклоняется сервером. |

## Локальный стенд

`scripts/dev-oidc.mjs` — тестовый провайдер с явным выбором Alice/Bob без паролей.
Он слушает только 127.0.0.1 и не предназначен для настоящих пользователей.
`scripts/studio-review-stand.mjs` запускает отдельные CMS (18093), Studio (18094),
OIDC (18095) и React-витрину (18096), создаёт проект `studio-work-review`,
роли автора/согласующего, manifest и ключ доставки staging. Секреты сохраняются
в локальные `*.private.json`, Studio работает в OIDC-режиме без сервисного fallback.
Остановка запускающего процесса через Ctrl+C завершает его дочерние процессы.

Подготовка: установленные зависимости, собранные Studio и React-store,
собранный `apps/server/cmd/cms`, отдельная мигрированная PostgreSQL на loopback,
свободные порты 18093–18096 и свежий каталог результатов вне Git. Создание
существующего тестового проекта не переиспользует его автоматически.

Перед запуском задайте `CMS_DATABASE_URL` защищённым локальным способом,
`CMS_REVIEW_BINARY` (абсолютный путь к бинарнику CMS), `CMS_REVIEW_DIR`
(абсолютный путь к каталогу результатов). Из корня репозитория:

```sh
node scripts/studio-review-stand.mjs
```

В другом терминале задайте `STUDIO_REVIEW_ADMIN_FILE` — путь к
`studio-work-admin.private.json` в каталоге стенда, `STUDIO_REVIEW_OUTPUT` —
каталог снимков. Для первого запуска свежего проекта:

```sh
node scripts/studio-live-review.mjs
```

Проверка действительно входит двумя браузерными сессиями через OIDC, назначает
им подготовленные роли, создаёт страницу от автора через Command API для
подготовки данных и далее работает через UI: сохранить текст и увидеть preview →
подать → сервер отклоняет самосогласование → второй человек согласует →
подтвердить публикацию → проверить committed документ и текст в приложении.
Проверяет исчезновение опубликованной работы из очереди и мобильную ширину.
Снимки: `studio-work-review.png`, `studio-work-mobile.png`,
`studio-work-published.png`. Этот сценарий меняет только фиксированный тестовый
проект; для повторной полной приёмки нужен свежий стенд. После первой публикации
на нём можно вручную создавать следующие черновики через «Страницы».

## Реализовано и оставшиеся зависимости

Реализован интерфейс очереди и карточки с существующим workflow. Локальная
приёмка двух OIDC-пользователей с реальным CMS/PostgreSQL и приложением прошла;
это не подключение внешнего IdP и не production-развёртывание. Выбор настоящего
провайдера, его регистрация клиентов и эксплуатационная конфигурация остаются
отдельными зависимостями. Серверный поиск очереди остаётся отдельным пакетом.
Сравнение версий всего CS добавлено в следующем
пакете, описанном ниже.

Синхронизация с Figma отложена. Пакет [сравнения изменений](studio-review-diff.md)
(STU-149…161) реализован, прошёл локальную приёмку и CI, слит в dev в PR #53.
[История публикаций и безопасный откат](studio-publication-history.md)
(STU-162…175) реализованы и слиты в dev в PR #54; локальная приёмка и CI пройдены.
Следующий пакет — [полная очередь работ и серверный поиск](studio-work-queue.md)
(STU-176…189): реализовано в рабочей ветке, локальная приёмка пройдена; CI — в PR. Новая спецификация
заменяет ограничения STU-144 на поиск по загруженным строкам и ключ CS/documentId;
остальные гарантии STU-145…148 сохраняются.
