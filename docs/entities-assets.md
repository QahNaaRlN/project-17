# Сущности и ссылки контента

## Пакет

Сущности создаются и редактируются через Change Set по контракту выбранного
окружения (`environment` в `entity.create`; для схемного CS — связанный кандидат).
Рабочие версии не меняют head/published. Поддерживаются локализованные поля,
проверка типов, unique и singleton, удаление/восстановление и undo/rebase.

Проверки публикации включают существующие опубликованные объекты и весь пакет:
ссылки entityId/assetId должны разрешаться в том же проекте и окружении либо
в публикуемом Change Set. Удаление с оставшимися ссылками блокируется с указанием
объектов-потребителей. Повторная проверка и запись проходят одной транзакцией.
Откат и promotion также проверяют ссылочную целостность.

## Граница

В этом пакете реализуются сущности и L2-ссылки, а также изменение метаданных уже
существующих ассетов. Выдача upload URL, S3/MinIO, MIME/SVG обработка, превью,
blurhash и imgproxy требуют следующего отдельного пакета загрузки ассетов.
Upcast и фоновая материализация CNT-023 также остаются отдельной задачей; более
новая schema_version отклоняется, более старая без реализованного upcast
блокируется явной диагностикой, чтобы не отдавать неверный контракт.

## Проверки

CNT-003/004/010–013/024/040/043: PostgreSQL сценарии совместной публикации,
неопубликованных и чужих ссылок, draft required warnings, unique/singleton,
удаления, отката, undo/rebase и атомарного отказа без изменения указателей/outbox.

## API и поведение

- `create-changeset` принимает необязательные `targets`, например `["production"]`.
  `entity.create` требует `schema`, `environment`, `data`; при первом создании
  выбранное окружение становится target CS. `entity.setFields` принимает `set`
  и `unset` с путями вроде `title.ru`; редактирование использует первый target
  CS (по умолчанию staging). Все targets проверяются при согласовании.
- `entity.delete` / `entity.restore` принимают пустой payload. Undo добавляет
  обратную операцию; отмена создания, как для документов, не поддерживается.
- `asset.updateMeta` допускает только `alt`, `title`, `focalPoint`, `tags`.
  Поля файла нельзя подменить этой операцией. Ассет должен уже существовать;
  пользовательские команды создания и загрузки ассетов пока не подключены.
- `GET /api/v1/entities/{id}` и `/assets/{id}` требуют `content.read`.
  Без `environment` читается head; `changesetId` выбирает рабочую версию.
  Закрытый CS позволяет читать неизменяемую историческую версию и после отката.
- `GET /delivery/v1/{project}/{env}/entity/{id}` и `/asset/{id}` используют
  существующие delivery/preview ключи. `/asset` возвращает метаданные, не бинарный
  файл. Опубликованные ответы имеют ETag и surrogate keys; preview — no-store.
  Выбор локали/fallback CNT-031 пока не реализован: данные возвращаются картами.

Согласование учитывает schema_version и tombstone. Promotion проверяет фактический
head (он не меняется при переносе), а publish — будущий head всего проекта.
