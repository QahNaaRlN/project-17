# Единый реестр компонентов — первый пакет

Реестр приложения связывает имя, контракт manifest, реализацию и проверку разрешённых
значений. Из одного объекта получаются `nativeDefinitions` для подготовки IR,
React-реестр и manifest для локальной сборки (MF-010). Витрина использует этот путь
вместо трёх вручную синхронизируемых таблиц.

Контракты свойств используют существующий формат `@cms/manifest`. React helper
выводит тип `values` из объявления свойств и проверяет совместимость компонента
при компиляции (часть MF-012). Полная fluent DSL `t.*`, действия, загрузчики,
автоматический `sourceRef`/индекс кода (MF-011), общий CLI и push после deployment
остаются следующими пакетами. Этот пакет не публикует контент.

Manifest проходит существующую структурную и семантическую валидацию перед записью;
хэш вычисляется по каноническому JSON (MF-001/MF-002). Метаданные копируются и
замораживаются, функции и реализации в JSON не попадают. Дубликаты имён запрещены.

`nativeDefinitions` сохраняет ограничения текущего runtime: responsive native props
поддерживают только `base`, именованные слоты native и обработчики событий пока
не выполняются. Проверка значений после bindings задаётся приложением через
`validate`; TypeScript не заменяет проверку входных данных. Объект с ключом `base` —
адаптивная обёртка; обычный object передавать внутри `base`.
