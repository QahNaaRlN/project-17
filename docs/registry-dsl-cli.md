# Registry DSL и CLI

Пакет реализует MF-001, MF-010, MF-011 и MF-012 для объявленных native
компонентов. Исходные обязательные требования сохраняются.

- Все типы manifest доступны через `t.*`; builders неизменяемы и превращаются
  в существующий JSON-контракт. Неподдерживаемые модификаторы запрещены типами,
  а ограничения и ссылки проверяет общий валидатор manifest.
- `defineComponent` проверяет обычные props реализации по объявлению, React
  adapter проверяет `NativeProps.values`. Оба пути поддерживают DSL и literal
  descriptors. Runtime использует тот же объект registry.
- `cms manifest build` проверяет TypeScript-проект, загружает его registry,
  автоматически определяет sourceRef через compiler API, создаёт manifest,
  canonical hash и code-index. Ошибка разрешения или неоднозначность источника
  останавливает сборку; вручную sourceRef не задаётся.
- Индекс содержит пути/экспорты/строки/связи и commit, без текста исходников.
  Зависимости — до глубины 2, тесты — прямые импорты реализации
  (AGT-070…072). Внешние и generated файлы исключаются.
- `cms manifest push` проверяет хэши manifest и индекса, использует service token
  из защищённого файла и существующий `register-manifest` (MF-004). Опция
  `--wait-for-deploy` ждёт точного хэша приложения, иначе регистрация не происходит
  (MF-005). Витрина отдаёт хэш сборки через `/.well-known/cms-manifest-hash`.
- Витрина использует DSL и общий CLI; seed берёт сгенерированные контракты.
  Полная реализация M3 этим пакетом не завершается.

[Следующий пакет](runtime-actions-data.md) добавил объявления/исполнение действий
и загрузчиков, а также их sourceRef и индекс. CLI исполняет
только доверенный код собственного приложения; CMS не исполняет этот код.
[Missing Capability](studio-missing-capability.md) добавляет сервисную команду
`upload-code-index`: CLI загружает проверенный индекс, затем передаёт upload ID
в register-manifest. Связь фиксируется атомарно по project/manifestHash/indexHash.
Canonical индекс ограничен 1 MiB; исходники не передаются. Непривязанные uploads
живут 24 часа, связанные сохраняются. Старый manifest без связи не обогащается
повторной регистрацией: нужна новая сборка с новым hash.
Поле `manifest.codeIndex.uploaded` остаётся исходным `false` и участвует в hash;
наличие подтверждённого индекса возвращает Query `codeIndexAvailable`.
Сборка не публикует контент и не разворачивает приложение.
