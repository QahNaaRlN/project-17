Статус: **черновик на одобрение; код не начат**.

[этапов pipeline 8–9](pipeline-render-checks.md)).
Основа: `origin/dev` на `682af26` (после [PR #88](https://github.com/QahNaaRlN/project-17/pull/88)).
Цель — критерий готовности MVP 4 ([план §3](spec/14-mvp-plan.md#3-критерии-готовности-mvp)):
нет открытых уязвимостей уровня high/critical, и требования безопасности
[12 §3](spec/12-security-ops.md#3-безопасность) выполнены и доказаны. Первый пакет

наблюдаемость → ADR → набор для эксперимента.

Сверка 2026-10-27 показала:

| SEC-007 сканеры в CI | Нет ни одного |
| SEC-008 анонимизация пользователя | Нет |

Локальные сканеры 2026-10-27:

- `govulncheck`: 32 вызываемые уязвимости — стандартная библиотека Go 1.26.0
  (исправлены в 1.26.10), `golang.org/x/net` v0.59.0 (исправлено в v0.60.0),
  тестовая `github.com/moby/go-archive` (через testcontainers).

  через Stryker, все в инструментах разработки; 14 moderate, среди них рантайм-
  зависимость `fast-uri` через `ajv` в `@cms/ir`.
- Образ сервера не сканировался.

Вне пакета: Row-Level Security (Q-07, после MVP), внешний пентест, WAF и
production-инфраструктура, наблюдаемость (отдельный пакет M6), смена модели
прав.

## 2. Требования

| ID | Требование |
|---|---|
| STU-500 | Job `Security` в `ci.yml` на каждый PR и пуш в `main`/`dev`: `govulncheck ./...` тулчейном модуля (отказ — любая вызываемая уязвимость), `pnpm audit --audit-level high` (production и dev-зависимости), сканирование образа сервера (решение §11.1) с отказом на high/critical. Job становится обязательным для PR в `dev` и `main` после первого зелёного прогона |
| STU-501 | Исключения — только файл `security/exceptions.json`: идентификатор, пакет, обоснование, кто принял, срок ≤ 90 дней. Просроченное исключение роняет job. Для high/critical исключений нет (решение §11.2) |
| STU-502 | Go: тулчейн 1.26.10 (`toolchain` в `go.mod`, образ сборки `golang:1.26.10-alpine`), `golang.org/x/net` ≥ v0.60.0, обновление testcontainers до версии без уязвимой `go-archive` или её замена через `replace`, если обновления нет |
| STU-503 | JS: `vite` ≥ 7.3.7, `vitest`/`@vitest/*` ≥ 4.1.12, `fast-uri` ≥ 3.1.9, `zod` ≥ 4.6.6, `qs` ≥ 6.16.0, `esbuild` ≥ 0.28.1 — обновлением прямых зависимостей или `pnpm.overrides` для транзитивных. Сборки, тесты и E2E не ослабляются |
| STU-504 | `security_events.project_id` допускает `NULL` для событий без проекта (вход человека); индекс `(project_id, created_at)`. Запись — общим помощником, в той же транзакции, что и действие, либо отдельной записью для отказов (как сейчас) |
| STU-505 | SEC-005, отказы: любой `401`/`403` Command и Query API — людям, сервисам и агентам — пишет `access.denied` с маршрутом или командой, требуемым правом и кодом; без тела запроса, параметров и секретов |
| STU-506 | SEC-005, входы: успешный вход OIDC — `auth.login`, отказ (неверный state, nonce, issuer, неактивный пользователь) — `auth.login_failed`, выход — `auth.logout`; данные — issuer, subject-хэш, причина; без токенов и cookie |
| STU-507 | SEC-005, токены и роли: выпуск токена (`bootstrap`, `check-runner-token`, сервисные токены) — `token.created` (ID токена, актор, области, срок), `create-role`, назначение и снятие роли — `role.*`, без секретов |
| STU-508 | SEC-005, политики: `set-approval-policy`, `set-agent-policy`, политики зон, `set-environment-app-url`, настройки GitHub и доставки — `policy.changed` с командой, версией/хэшем и причиной |
| STU-509 | Query `GET /api/v1/security-events?type=&after=&limit=` — право `project.admin`, события проекта с курсорной пагинацией (≤ 100); глобальные события проекта не видны (решение §11.4) |
| STU-510 | SEC-008: команда оператора `cms anonymize-user -issuer -subject` (CLI, решение §11.3): `display_name` → `Удалённый пользователь <хэш>`, `email`, `oidc_subject`, `oidc_issuer` → обезличены, `disabled_at` выставлен, сессии и токены отозваны, назначения ролей сняты; операции, CS, публикации и аудит сохраняются; событие `user.anonymized`. Повтор — без изменений |
| STU-511 | SEC-003: тест BFF Studio проверяет точный CSP, отсутствие инлайн-скриптов в `index.html` и `frame-ancestors 'none'` |
| STU-512 | SEC-004: ассеты отдаются с отдельного origin; для неизображений — `Content-Disposition: attachment`, всегда `X-Content-Type-Options: nosniff`; тест на каждый вид ответа ассета. Недостающее — доработать |
| STU-513 | SEC-006: тест проверяет подпись HMAC-SHA256 с меткой времени и отказ получателя на запрос старше 5 мин (по образцу приёмника в коде) |
| STU-514 | Изоляция проектов: табличный тест обходит все маршруты Query API и команды, принимающие ID объектов, и проверяет, что ID другого проекта даёт `404`/`403` без данных |
| STU-515 | Секреты в журналах: тест журналов CMS, Studio-BFF и исполнителя проверок на отсутствие токенов (`cms_svc_`, `cms_preview`, preview-JWT, cookie) в сценарии §2 (артефакт CI) |
| STU-516 | Модель угроз 12 §3.1: каждая угроза получает ссылку на меры и тест; отсутствующее доказательство — задача пакета или явный остаточный риск с ADR |
| STU-517 | Отчёт `docs/security-review.md`: SEC-001…008, модель угроз, результаты сканеров с датой и версиями, исключения, остаточные риски |
| STU-518 | Автоматические проверки: Go — события по каждому типу, `NULL`-проект, пагинация и доступ к журналу, анонимизация (повтор, отзыв, сохранность операций), изоляция; TS — CSP Studio |
| STU-519 | Документация: эта спецификация, 12 §3 (реализация), 08 (журнал, CLI), `docs/testing.md` (job `Security`), строка плана MVP, отчёт; критерий 4 отмечается выполненным только при зелёном job `Security` |

## 3. Порядок реализации после одобрения

1. Обновление тулчейна и зависимостей (STU-502, 503), локальные сканеры чистые.
2. Job `Security` и исключения (STU-500, 501).
3. Журнал событий и чтение (STU-504…509), анонимизация (STU-510).
4. Тесты требований и изоляции (STU-511…515).
5. Модель угроз, отчёт, документация (STU-516, 517, 519).

## 4. Критерии приёмки пакета

- Job `Security` зелёный на PR и обязателен для `dev` и `main`; high/critical нет.
- Каждое событие STU-505…508 появляется в журнале и не содержит секретов.
- Анонимизация не ломает историю: операции, публикации и согласования читаются.
- Существующие проверки, пороги покрытия и E2E не ослаблены.

## 11. Открытые вопросы и рекомендации

1. **Сканер образа.** Варианты: (а) Trivy (`aquasecurity/trivy-action`, базы
   уязвимостей ОС и Go-бинаря); (б) Grype. Рекомендация — (а): самый
   распространённый, умеет и образ, и `go.mod`, есть кэш базы в Actions.
2. **Исключения для high/critical.** Варианты: (а) не допускаются — только
   обновление или override; (б) допускаются для инструментов разработки с
   обоснованием и сроком. Рекомендация — (а): все найденные high сейчас
   исправимы обновлением, а критерий 4 сформулирован без оговорок.
3. **Кто анонимизирует пользователя.** Люди глобальны (вне проектов), роли
   «администратор установки» нет. Варианты: (а) CLI оператора `cms
   anonymize-user`; (б) новое глобальное право и команда API. Рекомендация — (а):
   без новой модели прав; оператор и так владеет БД и конфигурацией.
4. **Чтение журнала.** Варианты: (а) Query API для `project.admin` по своему
   проекту; (б) только БД. Рекомендация — (а): администратор проекта должен видеть
   отказы и смены политик без доступа к БД; глобальные события (входы) — оператору.
5. **Порог `govulncheck`.** Варианты: (а) отказ на вызываемые уязвимости (режим по
   умолчанию); (б) на любые в импортированных модулях. Рекомендация — (а): так
   работает `govulncheck`; невызываемые попадают в отчёт без отказа.
