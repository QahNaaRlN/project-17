# 11. CMS Studio

## 1. Стек

| Подсистема | Технология |
|---|---|
| Язык и UI | TypeScript, React |
| Сборка | Vite |
| Серверное состояние | TanStack Query (+ SSE `GET /api/v1/events` для инвалидации) |
| Локальное состояние | Zustand (выделение, режимы, буфер операций, UI-панели) |
| Drag & drop | dnd-kit |
| Структурный / кодовый редактор | CodeMirror 6 с JSON Schema IR (подсказки, проверка) |
| Совместное редактирование | Yjs — после MVP ([06 §4.3](06-changes-publishing.md#43-совместное-редактирование-после-mvp)) |

| ID | Требование |
|---|---|
| STU-001 | Studio — клиент публичных Command/Query API без привилегированных путей (FR-002). |
| STU-002 | Визуальный редактор реализуется собственными средствами; готовые page-builder фреймворки не используются как основа. |
| STU-003 | Формы свойств, палитра, пикеры токенов строятся из manifest, а не из кода Studio. |

```
┌───────────────────────────────────────────────────────────────────────────┐

│ Слои       │                                              │ Свойства     │

└───────────────────────────────────────────────────────────────────────────┘
```

## 3. Режимы одного документа

| Режим | Назначение | Ключевые требования |
|---|---|---|
| Visual | Прямое редактирование на холсте preview | Выбор, перетаскивание, вставка из палитры, inline-редактирование текста (создаёт `$local`), панели свойств |
| Structure | Дерево узлов и представление IR | Дерево слоёв с переименованием и перетаскиванием; CodeMirror с JSON узла/документа; правка в редакторе превращается в операции через diff (не в перезапись документа) |
| Agent | Изменение на естественном языке | Чат со встроенным агентом; шаги и операции агента видны в истории CS и сразу в preview; отмена любой операции агента |

| ID | Требование |
|---|---|
| STU-010 | Все режимы ДОЛЖНЫ работать с одним состоянием документа: выделение синхронизировано между холстом, деревом и редактором. |
| STU-011 | Правка JSON в режиме Structure ДОЛЖНА преобразовываться в минимальный набор операций каталога (diff нормализованных документов по ID узлов). Изменение, не выразимое операциями (например, смена ID), отклоняется. |

## 4. Панели

| Панель | Содержимое |
|---|---|
| Свойства | Поля `props` по типам manifest; контентные свойства — поле привязки (`$content`, `$local`, `$props`, `$item`…) с выбором пути из дерева доступных данных |
| Дизайн | Группы: Размещение, Отступы, Размер, Сетка/Поток, Фон, Типографика, Граница, Эффекты, Состояния. Пикеры токенов; сырые значения — только при разрешённом режиме, с отметкой «вне системы». Переключатель «для всех breakpoint'ов / только для текущего» |
| Данные | Основной контент страницы, источники данных, условие показа (`when`) в виде конструктора предикатов |
| Поведение | События узла → действия из manifest с формами аргументов; кнопка «Нужно поведение…» (Missing Capability) в зонах CODE |
| Политика | Зона: режим, `allowedTypes`, блокировка (только с `design.zones.manage`) |
| Контент | Список сущностей схем, редактор сущности (формы по схеме, rich text-редактор RichText v1) |
| Change Set | Операции с автором/источником, diff, проверки, согласования, конфликты и их разрешение |

## 5. Взаимодействие

| ID | Требование |
|---|---|
| STU-020 | Перетаскивание ДОЛЖНО показывать только допустимые места вставки (контейнеры, слоты, `allowedTypes`, эффективный режим, `locked`). |
| STU-021 | Операции применяются оптимистично в локальном состоянии и отправляются на сервер пакетами не реже раза в 150 мс; при отказе сервера локальное состояние откатывается, показывается диагностика. |
| STU-022 | Undo/redo (Ctrl/Cmd+Z, Shift+Ctrl/Cmd+Z) — через команды `undo`/`redo` (CHG §2.4). |
| STU-023 | Горячие клавиши: удаление, дублирование, копирование/вставка поддерева (между документами — с переназначением ID), группировка (`node.wrap`), выбор родителя (Esc), навигация по дереву стрелками. |
| STU-024 | «Сохранить как компонент» на выбранном поддереве открывает мастер `component.extract`: имя, какие привязки и свойства станут входами, слоты. |
| STU-025 | Studio показывает присутствие других пользователей на документе и их открытые CS (CHG-042). |
| STU-026 | Холст поддерживает режимы preview «Дизайн» / «Взаимодействие» (SDK-033) и показ границ зон. |

## 6. Качество Studio

| ID | Требование |
|---|---|
| STU-030 | Время до интерактивности Studio при открытии документа на 500 узлов — < 3 с (холодный кэш, 50 Мбит/с). |
| STU-031 | Перерисовка панели свойств при выборе узла — < 50 мс. |
| STU-032 | Сама Studio ДОЛЖНА соответствовать WCAG 2.2 AA для форм и навигации; холст — с клавиатурной альтернативой через дерево слоёв. |
| STU-033 | Интерфейс Studio на русском и английском (i18n с MVP). |
