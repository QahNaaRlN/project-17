# 05. Контент, схемы и ассеты

## 1. Схемы

Схема описывает тип контента. Схемы определяются в коде приложения и поставляются в manifest ([04-manifest.md §2.4](04-manifest.md#24-схемы-контента)).

```ts
export const article = defineSchema({
  name: "Article",
  version: 5,
  title: "Статья",
  display: { titleField: "title", previewField: "cover" },
  fields: {
    title:   t.text().required().localized().maxLength(200),
    slug:    t.string().required().unique().pattern("^[a-z0-9-]+$"),
    lead:    t.text().localized().multiline(),
    body:    t.richText().localized().blocks("paragraph", "heading", "bulletList", "image"),
    cover:   t.asset("image"),
    author:  t.reference("Author"),
    tags:    t.list(t.string()).max(10),
    publishedAt: t.datetime(),
  },
  migrateFrom: { 4: [m.rename("subtitle", "lead")] },
});
```

Сериализованная форма в manifest:

```json
"Article": {
  "version": 5,
  "title": "Статья",
  "singleton": false,
  "display": { "titleField": "title", "previewField": "cover" },
  "fields": {
    "title": { "type": "text", "required": true, "localized": true, "maxLength": 200 },
    "slug":  { "type": "string", "required": true, "unique": true, "pattern": "^[a-z0-9-]+$" }
  },
  "migrateFrom": { "4": [{ "op": "rename", "from": "subtitle", "to": "lead" }] }
}
```

| ID | Требование |
|---|---|
| CNT-001 | Имя схемы: `^[A-Z][A-Za-z0-9]{1,63}$`; имя поля: `^[a-z][A-Za-z0-9]{0,63}$`. Имена `id`, `schema`, `version`, `createdAt`, `updatedAt` зарезервированы. |
| CNT-002 | Версия схемы — целое, монотонно растущее. Сохранённая версия схемы неизменяема. Для standard действует общий реестр `(project_id, schema_name, version)`. Схемы preview сохраняются отдельными неизменяемыми снимками `(manifest_id, schema_name)` и не заполняют этот реестр: независимые preview могут использовать одинаковый номер версии с разным содержимым. При регистрации в standard проверяются общие версии, независимо от предварительной активации в preview (MF-033). |
| CNT-003 | `unique` гарантируется в пределах проекта среди head-версий сущностей схемы (для `localized` — в пределах локали). |
| CNT-004 | `singleton: true` — схема допускает ровно одну сущность (настройки сайта, футер). |

## 2. Сущности

Тело версии сущности:

```json
{
  "title": { "ru": "Летняя коллекция", "en": "Summer collection" },
  "slug": "summer-collection",
  "lead": { "ru": "Лён, хлопок и…" },
  "body": { "ru": { "type": "doc", "content": [] } },
  "cover": { "assetId": "0192f1c4-7a1e-7c2b-9d10-3b5f2a9e4c11", "alt": { "ru": "Модель в льняном костюме" } },
  "author": { "entityId": "0192f1c4-8b2f-7d3c-8e21-4c6a3baf5d22" },
  "tags": ["лето", "лён"],
  "publishedAt": "2026-06-01T09:00:00.000Z"
}
```

| ID | Требование |
|---|---|
| CNT-010 | Значение `localized`-поля — карта `локаль → значение`. Значение нелокализованного поля хранится напрямую. |
| CNT-011 | Ссылка хранится как `{ "entityId" }`. Ссылочная целостность проверяется при публикации: опубликованная версия не может ссылаться на сущность, не опубликованную в том же окружении (или публикуемую тем же Change Set). |
| CNT-012 | Удаление сущности — мягкое (`objects.deleted_at`) и выполняется через Change Set. Удаление сущности, на которую ссылаются опубликованные объекты, ДОЛЖНО отклоняться с перечнем ссылающихся объектов. |
| CNT-013 | Валидация тела по схеме выполняется при каждой операции; нарушение `required` в черновике — предупреждение, при публикации — ошибка. |

## 3. Rich text

**[Решение]** Rich text хранится как структурированный JSON (подмножество модели ProseMirror) — «RichText v1». HTML не хранится и не принимается.

```json
{ "type": "doc", "content": [
  { "type": "heading", "attrs": { "level": 2 }, "content": [{ "type": "text", "text": "Материалы" }] },
  { "type": "paragraph", "content": [
    { "type": "text", "text": "Только " },
    { "type": "text", "text": "натуральный лён", "marks": [{ "type": "bold" }] },
    { "type": "text", "text": ", подробнее ", "marks": [] },
    { "type": "text", "text": "в журнале", "marks": [{ "type": "link", "attrs": { "to": { "kind": "page", "page": "0192…" } } }] }
  ] }
] }
```

| Категория | Элементы |
|---|---|
| Блоки | `paragraph`, `heading` (`level` 2…4), `bulletList`, `orderedList`, `listItem`, `blockquote`, `image` (`assetId`, `alt`), `divider` |
| Инлайн | `text`, `hardBreak` |
| Метки | `bold`, `italic`, `underline`, `strike`, `code`, `link` (`to`: Link) |

Поле схемы МОЖЕТ ограничить допустимые блоки и метки. Runtime рендерит RichText через примитив `RichText`; стили элементов задаются токенами `typography`.

## 4. Миграции схем

### 4.1. Классы изменений

| Изменение | Класс | Требует миграции |
|---|---|---|
| Новое необязательное поле; новое значение enum; ослабление ограничения | совместимое | нет |
| Новое обязательное поле с `default` | совместимое | нет (значение по умолчанию при чтении) |
| Удаление, переименование поля; смена типа; поле стало обязательным без `default`; сужение ограничений; `localized` включён/выключен | несовместимое | да, `migrateFrom` |

### 4.2. Декларативные операции миграции

| Операция | Действие |
|---|---|
| `rename {from, to}` | Переименовать поле |
| `drop {field}` | Удалить поле |
| `setDefault {field, value}` | Заполнить отсутствующие значения |
| `localize {field}` | `v` → `{ <defaultLocale>: v }` |
| `delocalize {field, locale}` | `{…}` → значение локали |
| `wrapList {field}` / `unwrapList {field}` | `v` ↔ `[v]` |
| `mapEnum {field, map}` | Замена значений enum |
| `convert {field, to}` | Встроенные преобразования: `toString`, `toNumber`, `textToRichText`, `richTextToText` |

Миграции, не выразимые этими операциями, выполняются внешним скриптом через Command API от актора `migration`.

### 4.3. Применение

| ID | Требование |
|---|---|
| CNT-020 | Миграции ДОЛЖНЫ быть чистыми функциями тела сущности. Это позволяет применять их при чтении. |
| CNT-021 | Регистрация manifest стандартного окружения с изменёнными схемами создаёт Change Set вида `schema` с операциями `schema.apply`. Manifest сохраняется кандидатом и не активируется до публикации этого CS (MF-025–MF-027). Его применение требует права `schema.apply` и проходит согласование по политике. Исключение для изолированного preview — MF-033; публикация контента в preview остаётся запрещённой. |
| CNT-022 | В Change Set схемы анализ влияния ДОЛЖЕН находить документы IR, привязки которых ломаются изменением. Такие документы ДОЛЖНЫ исправляться в том же Change Set; иначе публикация блокируется. |
| CNT-023 | После публикации схемы чтение сущности с более старой `schema_version` выполняет upcast цепочкой `migrateFrom` «на лету». Фоновая задача материализует новые версии сущностей пакетами по 500 от актора `migration`, сдвигая head и published указатели только если они указывали на мигрируемую версию. |
| CNT-024 | Окружение использует версию схемы из своего активного manifest; при проверке и атомарной публикации связанного CS схем используется кандидат, который становится активным в той же транзакции. Публикация версии сущности, записанной по схеме новее, чем активная в целевом окружении, запрещена (`SCHEMA_VERSION_AHEAD`). Даункаст не поддерживается. |

## 5. Локализация

| ID | Требование |
|---|---|
| CNT-030 | Проект объявляет `locales` и `defaultLocale`. Каждая локаль МОЖЕТ иметь цепочку fallback (`"kk": ["ru"]`). |
| CNT-031 | Delivery API возвращает значения для запрошенной локали с применением fallback; в ответе отмечаются поля, полученные через fallback. |
| CNT-032 | Модель данных поддерживает локализацию с MVP. Интерфейс параллельного редактирования локалей, статусы перевода и полнота локалей — после MVP. |

## 6. Ассеты

### 6.1. Загрузка

Реализованный серверный путь и текущие границы обработки описаны в
[пакете загрузки ассетов](../asset-upload-processing.md). После обработки готовый
файл явно добавляется в Change Set через `asset.create {uploadId}` или
`asset.replaceFile {set:{fileHash}}`; worker не изменяет контент и публикации.

```
create-asset-upload {filename, mimeType, size, sha256}
   ─▶ { assetId, uploadUrl (pre-signed PUT, 15 мин) }
клиент ─PUT─▶ S3/MinIO
complete-asset-upload {assetId}
   ─▶ задача обработки: проверка MIME по содержимому, метаданные, превью, blurhash
```

| ID | Требование |
|---|---|
| CNT-040 | Ассет — объект `kind = asset`. Метаданные (`alt` (локализуемый), `title`, `focalPoint`, `tags`) версионируются; бинарный файл неизменяем и адресуется SHA-256 (дедупликация). Замена файла создаёт новую версию ассета. |
| CNT-041 | Допустимые типы и лимиты по умолчанию: изображения `jpeg, png, webp, avif, gif, svg` ≤ 25 МиБ; видео `mp4, webm` ≤ 500 МиБ; файлы `pdf` ≤ 100 МиБ. Проект МОЖЕТ сузить список. |
| CNT-042 | MIME ДОЛЖЕН определяться по содержимому; расхождение с заявленным — отказ. SVG ДОЛЖЕН санитизироваться (удаление скриптов, обработчиков событий, внешних ссылок, `foreignObject`). |
| CNT-043 | Ассет недоступен через Delivery API, пока не опубликован в окружении (как любой объект). |

### 6.2. Трансформации изображений

| ID | Требование |
|---|---|
| CNT-050 | Изображения отдаются через `/assets/v1/{env}/{assetId}/{fileHash}?w=&h=&fit=&fmt=` за CDN. Обработку выполняет imgproxy; URL подписываются, чтобы ограничить множество вариантов. |
| CNT-051 | Допустимые ширины: 320, 480, 640, 768, 1024, 1280, 1600, 1920, 2560. Форматы: `avif`, `webp`, `jpeg`, `png`. |
| CNT-052 | Runtime-примитив `Image` ДОЛЖЕН формировать `srcset`/`sizes` по адаптивной ширине узла и учитывать `focalPoint` при `fit: cover`. |

## Текущее состояние реализации

Создание/редактирование/удаление/восстановление сущностей через CS, схемная проверка,
unique/singleton, L2-ссылки, метаданные ассетов, HTTP и Delivery чтение подключены
([граница и API](../entities-assets.md)). Upload pipeline CNT-041/042, S3/MinIO,
imgproxy, upcast/материализация CNT-023 и locale fallback CNT-031 ещё не реализованы.
Старые версии требуют явного исправления в CS; новые относительно окружения
отклоняются с `SCHEMA_VERSION_AHEAD`. Даункаст не выполняется.
