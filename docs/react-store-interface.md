# Первая React-витрина

## Объём и критерии

Реализован выбранный вариант «Каталог в центре» для `examples/react-store`.
Это приложение на React/TypeScript/Vite с серверным чтением Delivery API через
`@cms/core`, адаптивными изображениями `@cms/runtime` и диалогом Radix в стиле
shadcn. Tailwind обслуживает стили приложения. Контент хранится в документе CMS
в native-компоненте `Storefront` с типизированным входом `config`.

Критерии первого пакета (STORE-001…008):

1. Страница, названия, описания, цены и список предметов читаются из CMS. Пример
   работает без браузерного delivery/service/preview ключа (STORE-001).
2. Компактный каталог адаптируется от 320 px до компьютера; меню на телефоне
   раскрывается с клавиатуры (STORE-002).
3. Подробнее открывает выбранный предмет, Escape закрывает диалог, фокус
   возвращается к инициатору (STORE-003).
4. SSR выдаёт текст страницы и карточки до выполнения JavaScript, клиент
   гидратирует интерфейс без расхождения (STORE-004).
5. Повтор запроса действительно читает CMS; загрузка, пустая подборка, ошибка
   чтения и отсутствующее/не загрузившееся изображение имеют явные состояния
   (STORE-005).
6. Signed images используют srcset/sizes; модель обновляется до истечения URL.
   Неизвестная цена отображается как «Цена не указана», а не 0 (STORE-006).
7. Неверный config отклоняется; строка контента не становится HTML/скриптом.
   Секреты и сообщения внутренних исключений не сериализуются (STORE-007).
8. Автоматические проверки включают модель/сервер и браузерные сценарии для
   адаптивности, загрузки, повторов, диалога и гидратации (STORE-008).

## Границы

Пример не реализует универсальный `@cms/react` renderer, Repeat/Composed,
вычисление произвольных bindings/условий, runtime-генерацию атомарного CSS,
реестр/CLI manifest, Studio или secure preview bridge. `Storefront` — явно
зарегистрированный native-компонент приложения. Его вход передаётся как
`config: {base: {...}}`: обычный object внутри base по правилу IR.
Breakpoint overrides config в этом пакете отклоняются, а не игнорируются.
Адаптивность native-компонента реализует CSS приложения.

Контент первого примера хранится в документе, не в сущностях Product. Перенос
на сущности и общий data loader требует отдельного контракта и схемного
lifecycle, а не скрытой подмены backend-данных. Цены — демонстрационные целые
рубли с явным названием `priceRub`, ограниченные допустимым диапазоном.
Корзина, оплата и заказы в пример не входят.

Локальное заполнение создаёт новый Change Set, ассеты и preview-токен. Ничего
не публикует. Конфигурация доступа хранится вне репозитория в защищённом файле;
Собранная версия поддерживает локальный preview и опубликованную страницу
с delivery key; `NODE_ENV=production` выбирает режим сборки, а не публичное размещение.
Пример запускается только на loopback. Публичный production deploy и управление
доступом пользователей остаются отдельным шагом.
