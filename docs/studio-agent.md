# Studio Agent и MCP

Пакет STU-120…125 реализует первый сквозной Agent: текущий пользователь явно
запускает задачу в своём открытом CS; сервер обращается к OpenRouter, исполняет
семантические инструменты и показывает шаги, результат, расход и остановку.

| ID | Контракт |
|---|---|
| STU-120 | `register-agent`, `start-agent-session`, `end-agent-session`: отдельный actor.kind=agent, токен `cms_agt_`, TTL ≤8 ч, квота операций и явный список CS. Studio не получает этот токен. |
| STU-121 | Права сессии ограничены снимком делегированных прав, текущими правами человека и текущей политикой агента. Отзыв, блокировка и потеря agent.delegate прекращают новые запросы. Command Bus повторно проверяет сессию в транзакции, квота расходуется только на новые зафиксированные команды. |
| STU-122 | Операции сохраняют agent actor, onBehalfOf, session, reason и source=agent. Сессия не позволяет менять чужой/неразрешённый CS. Публикация, согласование, изменение прав/политик и схем недоступны агенту. Риск агентского CS ≥medium, требуется минимум одно человеческое согласование. Автор/делегат не согласует собственные изменения. |
| STU-123 | `/mcp`: Streamable HTTP с JSON-ответами, initialize/ping/tools/list/tools/call. Общий каталог используется встроенным Agent. `packages/mcp` предоставляет описания и stdio-прокси. Сервер валидирует Origin, токен, аргументы, CS и expectedSeq. Данные документов отделены от описаний инструментов. |
| STU-124 | OpenRouter вызывается только сервером после явного запуска. Ключ — CMS_OPENROUTER_API_KEY; модель задаёт администратор проекта через set-agent-config, либо серверный CMS_OPENROUTER_MODEL. Без ключа/модели показывается недоступность. Ограничены размер контекста, ответы, шаги, время и операции. Нет внешних сетевых инструментов, исполнения кода или доступа к секретам. |
| STU-125 | Запуск ставится в River в транзакции команды. Шаги/usage сохраняются; SSE уведомляет только владельца. Отмена отзывает сессию; новые операции после неё блокируются. При потере ответа провайдера расход остаётся неизвестным с консервативной резервацией, а запрос не повторяется автоматически. Потеря процесса даёт interrupted, не скрытый повтор LLM. |

Команды: `set-agent-policy`, `set-agent-config`, `start-agent-run`, `cancel-agent-run`.
Внешнее делегирование: `register-agent`, `start-agent-session`, `end-agent-session`.
Клиент внешнего агента создаёт случайный 256-битный секрет `cms_agt_` + base64url
и передаёт в start-agent-session только SHA-256 полного секрета в `tokenHash`
(base64). Ответ содержит id/agentId/expiresAt, без секрета. Идемпотентный ответ
также не содержит токен; в БД хранится только хэш. Секрет остаётся в окружении
клиента MCP. Встроенный Agent использует серверный session id, не bearer в браузере.
MCP и встроенный оркестратор используют один каталог: `get_changeset`,
`get_page_structure`, `list_schemas`, `get_capabilities`, `insert_node`, `move_node`,
`remove_node`, `update_props`, `update_design`, `bind_data`, `set_behavior`,
`set_local_content`. Это ограниченный первый набор; get_node, поиск/создание
сущностей, компоненты, preview/review tools и полный каталог AGT-010 остаются
дальнейшим расширением. Агент может изменять композицию и локальный текст;
задачи вне каталога завершаются объяснением отсутствующей возможности.
Query API: `GET /api/v1/agent-config`, `/agent-runs` (documentId/changesetId/environment),
`/agent-runs/{id}`. Чужие задачи не выдаются. Задача привязана к странице и CS;
изменяющие инструменты требуют reason и optimistic expectedSeq. Undo выполняет
человек через существующую историю. Переключение CS не переносит локальный prompt.

MVP-политика проекта задаёт allow/deny rights с deny-first и постоянным запретом
привилегированных действий. Условные правила §09.2.3 и partitioned security_events
остаются укреплением; проверки IR/manifest/зон продолжают использовать общие
валидаторы. Проверка публикации заново пересекает записанные права с текущей
политикой и правами делегата, даже после окончания сессии.

Месячный лимит — токены, календарный месяц UTC. Учитываются prompt/completion
по проекту и пользователю; отсутствующее usage не трактуется как ноль. Перед
каждым запросом атомарно резервируется консервативный верхний предел. Ответ
провайдера не создаёт CMS-фактов сам: инструменты проходят Command Bus.
Резервация использует байты сериализованного контекста, запас на схемы/обрамление
и max_tokens; превышение отчётом провайдера блокирует исполнение инструментов
и сохраняет фактический расход. Остаток показывается как резерв, не как ноль.

OpenRouter: [tool calling](https://openrouter.ai/docs/guides/features/tool-calling),
[provider routing](https://openrouter.ai/docs/guides/routing/provider-selection).
Запрос использует только заданную модель, require_parameters=true,
data_collection=deny и allow_fallbacks=false. Реальный ключ, модель и живой
вызов провайдера относятся к настройке окружения; тесты используют HTTP boundary.
MCP: [Streamable HTTP 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports).
