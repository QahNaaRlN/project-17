# A11Y и согласование зон

Пакет реализует статические правила 03-design-system §6 и PUB-001 для
requiredApprovalRole. L7 возвращает предупреждения при редактировании и undo;
ошибки блокируют подачу, согласование, публикацию и продвижение. Предупреждения
порядка заголовков и контраста raw не блокируют публикацию.

Проверяется итоговое дерево страницы с точными версиями Composed и заполнением
слотов. Заголовки и вложенная интерактивность учитываются через границы компонентов.
Адаптивная видимость учитывается отдельно для каждого breakpoint.
Контраст проверяется по известным цветам, breakpoint и темам; неизвестный фон,
динамические значения и CSS-цвета, которые нельзя вычислить статически, не дают
ложного результата. Динамические axe-проверки требуют будущего preview/runtime.
Формула контраста: [W3C G18](https://www.w3.org/WAI/WCAG21/Techniques/general/G18).

Роли затронутых зон собираются из исходного и итогового документа: удаление или
перенос зоны не снимает требования согласования. Учитываются также изменения
live-компонентов в опубликованных потребителях целевых окружений, включая
внутренние зоны исторических закреплённых обёрток. Изменение экземпляра Composed
учитывает внутренние зоны точной версии компонента. Роль — имя
project-scoped роли, а не capability и не значение из клиентского payload.

Для каждой обязательной роли нужен хотя бы один независимый человек с текущим
членством и content.publish. Один согласующий может покрыть несколько ролей.
Число согласований по риску сохраняется; при обязательных ролях оно не ниже одного.
Изменение STRICT-зон повышает риск до high. В ответах проверки видны requiredRoles
и missingRequiredRoles. Перед публикацией роли проверяются повторно: отзыв роли
или отключение согласующего отклоняет команду без изменения данных публикации.

Регистрация/активация manifest, схемная публикация и динамический pipeline остаются
следующими пакетами. Формат IR и manifest не меняется.
