## 1. Результат и границы

Дизайнер в CODE-зоне может запросить два оставшихся вида возможностей:

- **Источник данных.** Страница должна показывать данные, которых нет среди
  источников manifest (например, «рекомендации к товару»). Дизайнер описывает
  параметры и форму результата, подключает к странице **заглушку источника**
  под своим ключом `$data.<key>` и сразу строит привязки и повторы по
  предложенной форме. До реализации preview показывает пустое состояние, а
  публикация заблокирована.
- **Токен дизайн-системы.** Значения нет среди токенов manifest (например,
  отступ `3xl` = 48px). Дизайнер задаёт категорию, имя и предлагаемое значение;
  в выбранном дизайн-свойстве узла появляется **заглушка токена**, preview
  показывает предлагаемое значение, публикация заблокирована.

Дальше путь общий с действиями и компонентами: context pack разработчику, PR,
проверенное слияние, активация manifest с совместимым элементом, автоматическая
замена системой `cms-system` во всех привязках группы (STU-338…347), обычные
проверка, согласование другим человеком и публикация.

В границах: виды `dataSource` и `token` (контракты, имена, заглушки в IR, их
проверки), отправка с записью заглушки, присоединение к группе, context pack,
поведение в preview, совместимость и автоматическое/ручное выполнение, узкие
права `cms-system`, агентский черновик, Studio RU/EN, миграция 00026, локальная
приёмка обоих видов.

Вне границ: токены типографики и тем (составные значения, DS-003), образцы
данных для preview (решение §11.3), изменение значения существующего токена,
генерация кода загрузчика, автоматическое открытие PR, условные политики агента
(следующий пакет), изменение опубликованных версий.

## 3. Требования

| ID | Требование |
|---|---|
| STU-375 | Запрос получает `kind: dataSource` или `kind: token`. Ключ источника — точечное имя manifest (как у действий); ключ токена — `<категория>.<имя>`, имя по DS-001, категория из `spacing, colors, radius, shadow, borderWidth, container, layer, transition`. Ключ не совпадает с элементом активного manifest и с открытым запросом того же вида (STU-258). Тексты — лимиты STU-256 |
| STU-376 | Контракт источника: `params` (до 16 полей, типы manifest §4), `result` (тип manifest, глубина ≤ 8, без `content: true`), `paginated`. Контракт токена: `category`, `value` — значение категории (длина, цвет, тень, длительность, целое), проверяемое как в manifest. Неизвестные поля отвергаются |
| STU-377 | Заглушка источника — подключение `dataSources.<key> = {source: <ключ запроса>, pending: <id>, params}` только на странице, в черновике, при CODE-режиме документа. `$data.<key>` типизирован предложенным результатом; параметры проверяются по предложенным `params` |
| STU-378 | Заглушка токена — дизайн-значение `"pending:<id>"` в свойстве (базовое значение, breakpoint или состояние) узла в эффективной CODE-зоне. Категория свойства должна совпадать с категорией запроса; иначе `CAPABILITY_PENDING_INVALID` |
| STU-379 | Публикация документа с заглушкой источника или токена отклоняется (`DATA_SOURCE_PENDING_CAPABILITY`, `TOKEN_PENDING_CAPABILITY`), как STU-269/358. Заглушка неизвестного, чужого, черновикового или терминального запроса — `CAPABILITY_PENDING_INVALID` при операции и проверке |
| STU-380 | Мастер источника — в панели «Источники данных» страницы: «Нужен другой источник…» (ключ подключения, ключ источника, параметры и их начальные значения, форма результата, `paginated`, тексты). Мастер токена — у дизайн-свойства узла: «Нужен другой токен…» (имя, значение категории свойства, тексты). Похожие элементы manifest и открытые запросы показываются до создания; ручного JSON нет |
| STU-381 | Draft не меняет IR. Отправка в одной транзакции проверяет revision/seq/manifest, место и права, строит pack и записывает `document.setDataSource` с заглушкой либо `node.setDesign` со значением `pending:<id>`. Повтор идемпотентен |
| STU-382 | Права: создание — capability.request + design.read; отправка, присоединение, снятие — design.compose, владение CS, CODE-режим, locked/primary-content проверки; для источника с параметрами из основного контента — content.read (как `document.setDataSource`) |
| STU-383 | Привязки: `anchor_kind = source` (ключ подключения на странице) и `anchor_kind = design` (узел и путь свойства, например `padding@md`). Миграция 00026 расширяет CHECK видов и привязок; лимиты STU-335 общие |
| STU-384 | Присоединение: другой CS подключает тот же запрос источника под своим ключом или ставит тот же токен в другое свойство — группа STU-336/337. Отсоединение — удаление подключения (`document.setDataSource null`) или значения свойства обычной операцией |
| STU-385 | Операции над заглушками: изменение параметров и привязок к `$data.<key>` — по предложенному контракту; смена `source` или подмена `pending` вручную — `CAPABILITY_PENDING_INVALID`; копирование страницы/узла с заглушкой не создаёт привязку и отклоняется так же; удаление — обычная правка, привязка `anchor_changed` |
| STU-386 | Context pack источника: контракт, ключ подключения, начальные параметры, привязки страницы к `$data.<key>` (пути и типы, без значений), похожие источники manifest и их записи индекса кода. Pack токена: категория, имя, значение, токены той же категории manifest и место в registry. Лимиты STU-265 |
| STU-387 | Preview: заглушка источника не вызывает загрузчик; `$data.<key>` в preview — состояние «нет данных» (`CMS_SOURCE_PENDING`), повторы показывают пустой слот. Заглушка токена в preview черновика рендерится предлагаемым значением (подстановка только в ответе preview и в мосте Studio); published/Delivery API заглушек не содержат |
| STU-388 | preview/<ref>: при совместимом элементе в manifest PR источник исполняется настоящим загрузчиком, токен — настоящим `var(--cms-…)`; подстановка только в ответе этого preview (как STU-320/367) |
| STU-389 | Совместимость источника: предложенные параметры есть с совместимыми типами, обязательные параметры manifest без default предложены, результат manifest совместим с предложенным (содержит его поля с совместимыми типами), `paginated` совпадает. Совместимость токена: токен есть в категории; значение может отличаться — оно записывается в основание выполнения |
| STU-390 | Выполнение — условия STU-339, outbox, повторы и бюджеты без изменений. Замена: `document.setDataSource` без метки `pending` и `node.setDesign` со значением-именем токена; `cms-system` может выполнять только эти изменения на живых привязках выполненного запроса (STU-345); группа по CS, undo → `reverted`, повтор, CS на проверке — STU-342…347. Ручной resolve — «Применить доступный источник/токен» |
| STU-391 | Агент: `report_missing_capability` создаёт draft вида `dataSource` или `token` в разрешённом CS; заглушки агент не ставит и resolve не выполняет (STU-271) |
| STU-392 | Studio: мастера STU-380, бейджи «Ожидает источник»/«Ожидает токен» в панелях и Structure, карточка запроса по виду, раздел «Выполнение» без аргументов для этих видов. RU/EN, клавиатура, 375 px, dirty guard, exact retry |
| STU-393 | IR-схема Go/TS, миграция, команды, операции, pack, runtime, Query, Studio и отрицательные сценарии покрыты тестами с ID требований; conformance-фикстуры заглушек; инъекция сбоя новых записей. Покрытие Go ≥ 95% с запасом; пороги не снижаются, исключения не добавляются |

## 4. IR и модель данных

Заглушка источника (решение §11.2):

```json
"dataSources": {
  "recommended": {
    "source": "store.recommendations",
    "pending": "0192f1c5-6a1e-7c3b-9d40-2f1e0c3b9a11",
    "params": { "limit": { "lit": 4 } }
  }
}
```

Заглушка токена — значение свойства дизайна:

```json
"design": { "padding": { "base": "md", "lg": "pending:0192f1c5-…" } }
```

- `dataSourceUse` получает необязательное поле `pending` (UUID); схема IR 1.0,
  Go/TS-валидаторы и conformance-фикстуры обновляются вместе. Документы без
  метки не меняются; старый валидатор поле игнорирует.
- Строка `pending:<uuid>` уже допустима схемой дизайн-значения; смысл ей
  придают проверки L3/L4 (§5) и runtime (STU-387).
- Проверки берут определения заглушек из контрактов запросов через overlay
  STU-357: `dataSources[<ключ>]` и `tokens[<категория>][pending:<id>]` для
  проверки и рендера preview.

Миграция 00026:

- `capability_requests.kind` — `action`, `component`, `dataSource`, `token`;
  `placement` хранит ключ подключения или узел/путь свойства.
- `capability_request_anchors.anchor_kind` — `event`, `node`, `source`, `design`;
  для `source` в `node_id` хранится ключ подключения, для `design` событие
  заменяет путь свойства.

| Команда | Изменение payload | Кто |
|---|---|---|
| create-capability-request | `kind`, `placement {dataSourceKey}` и `initialParams` либо `placement {nodeId, property, breakpoint?, state?}`; контракт вида | capability.request + design.read |
| submit-capability-request | IR-жест — `document.setDataSource` или `node.setDesign` с заглушкой | + design.compose, владелец CS, CODE |
| attach-capability-request | Своё `placement` для нового экземпляра | + design.compose |
| resolve-capability-request | Без `handlers`; IR-жест — снятие метки или подстановка имени токена | + design.compose |

## 5. Проверки, preview и выполнение

- **Источник.** Overlay добавляет предложенный контракт в `dataSources` manifest
  только для этой проверки; привязки к `$data.<key>` проверяются как обычно.
  Каждая заглушка — ошибка публикации `DATA_SOURCE_PENDING_CAPABILITY`.
- **Токен.** Значение `pending:<id>` живого запроса той же категории не даёт
  `TOKEN_UNKNOWN`; проверки контраста (a11y) используют предлагаемое значение.
  Каждая заглушка — ошибка публикации `TOKEN_PENDING_CAPABILITY`.
- **Runtime.** Заглушка источника не загружается: `$data.<key>` получает
  ошибку `CMS_SOURCE_PENDING` с пустым результатом; приложения, отклоняющие
  страницы с диагностиками, должны допускать её в preview (как
  `CMS_COMPONENT_PENDING_CAPABILITY`). Для токена preview получает документ, где
  `pending:<id>` заменено `{raw: <значение>}`; хранимые версии не меняются.
- **Выполнение.** Проверки STU-339 и совместимость STU-389; затем по CS одна
  группа операций `cms-system`: снять метку `pending` у подключения или
  записать имя токена. Повторная проверка под блокировкой: подключение/свойство
  содержит ровно заглушку запроса; иначе `anchor_changed`; ошибки по настоящему
  определению — `invalid_props`.

## 6. Отказы и диагностики

| Код / состояние | Когда |
|---|---|

| `CAPABILITY_CONTRACT_INVALID` | Контракт нарушает STU-376 |

## 7. Studio

«Источники данных» страницы: «Нужен другой источник…» — сначала похожие
источники manifest и открытые запросы, затем мастер: ключ подключения на
странице, ключ источника, параметры (тип, обязательность) и их начальные
значения, форма результата (объект с полями или список объектов),
`paginated`, тексты, предпросмотр pack. После отправки подключение видно в
панели с бейджем «Ожидает источник», привязки и Repeat строятся по
предложенной форме.

Дизайн-свойство узла: рядом с выбором токена — «Нужен другой токен…»: имя,
значение в форме категории (длина, цвет и т.д.), breakpoint/состояние, тексты.
Свойство показывает бейдж «Ожидает токен 3xl», холст — предлагаемое значение.

Карточка запроса и раздел «Выполнение» — общие, по виду: без аргументов,
состояния `invalid_props`/`anchor_changed` со ссылкой на место. RU/EN,
клавиатура, focus/Escape, 375 px, dirty guards, exact retry.

## 11. Принятые решения — 2026-10-21

Пользователь одобрил спецификацию и принял рекомендации по всем вопросам.

1. **Состав пакета.** Оба вида в одном пакете: общая инфраструктура делается один раз.
2. **Заглушка источника.** `source` = ключ запроса и метка `pending`; привязки к
   `$data.<key>` при выполнении не меняются (STU-377, §4).
3. **Данные в preview.** Без образцов — пустое состояние «нет данных» (STU-387).
4. **Значение токена в preview.** Предлагаемое значение подставляется `raw` только
   в preview; публикация невозможна (STU-387).
