## 1. Результат и границы

Редактор подключает зарегистрированный приложением источник к странице,
задаёт параметры формой, выбирает список результата и создаёт Repeat.
Внутри шаблона он связывает свойства блоков с полями элемента, настраивает
пустое состояние и видит реальные данные в preview. Всё сохраняется в своём
открытом standard CS и проходит существующее согласование и публикацию.
ID, JSON и выражения для этого пути вводить вручную не требуется.

Приёмочный путь: Collection как основной контент → параметр источника из
поля Collection → Repeat по результату → заголовки и изображения элементов
→ пустая коллекция → восстановление списка → согласование другим человеком
→ публикация. Источник реализуется в коде приложения и заранее присутствует
в активном manifest. Studio настраивает использование существующего источника.

Входят прямые `$data`-привязки, списки в корне результата или полях объектов,
один уровень создаваемых Repeat, `$item` и его поля, числовой limit и стабильный
ключ элемента. Поддерживаются обычные и `paginated` источники; у последних
показывается только первая порция с явным пояснением об ограничении.

Не входят конструктор событий/действий и `data.loadMore`, пагинация интерфейса
витрины, конструктор when, форматтеры/шаблоны/fallback, создание вложенных Repeat,
редактор `$props`/`$each`/`$index`, component.extract, обход entity-reference,
произвольный HTTP/SQL/JS, граф зависимых источников, общий кэш результатов,
конструктор схем, Missing Capability, Figma и production-развёртывание.
Это часть M4 и шага 4 MVP; component.extract и полный IR-044 остаются отдельными.

## 4. Декларация и серверная операция

Реализованная операция:

```json
{
  "type": "document.setDataSource",
  "target": "<pageObjectId>",
  "payload": {
    "key": "featured",
    "use": {
      "source": "commerce.products.list",
      "params": {
        "collection": "$content.handle",
        "limit": { "lit": 4 }
      }
    }
  }
}
```

`use: null` удаляет ключ; отсутствие use ошибочно. Запись заменяет ровно одно
подключение, а не всю map. Последний удалённый элемент убирает пустую dataSources;
inverse восстанавливает точное предыдущее значение. Ключи с prototype pollution
(`constructor`, `prototype`, `__proto__`) запрещены на всех границах, даже если
регулярное выражение identifier допускает часть из них. Максимум — 64 подключения,
с сохранением общего runtime-предела 64 с экземплярами Composed.

В этом пакете операция доступна page-only и требует `design.compose`, открытый
собственный standard CS и разрешение эффективной политики. Новая роль не вводится.
Чтение `$content` и каталог сущностей требуют `content.read`; при отсутствии права
не раскрываются значения/названия недоступного контента. Ограничение page-only
не запрещает чтение старых component-документов с dataSources.

Нужны регистрация каталога операции, строгий payload, audit before/after,
inverse/undo/redo, workflow classification, rebase и conflict pointers,
Studio optimistic reducer, JSON diff и проверка публикации. Операция не вызывает
загрузчик. Свойства схемы и операционный контракт должны иметь общие Go/TS
фикстуры. `apply-operations` сохраняет существующие envelope/лимиты.

Атомарная группа допускает промежуточные неполные привязки; L1 проверяется
по действующим правилам, manifest/области — на конечном документе группы.
Невалидный payload отклоняется; существующая политика черновых L2-диагностик
сохраняется. Submit/publish не пропускают ошибки контрактов и областей.
При потере ответа повтор использует исходные seq/idempotency key/operations.
При конфликте форма сохраняет ввод и предлагает перечитать, без слепого повтора.

Ключ существующего подключения в первой версии не редактируется. Новый ключ —
отдельное подключение; удаление старого проходит анализ зависимостей. Замена
source/result должна проверять не только bindings, но и when/on, параметры
источников, key и зависимости внутри сложных выражений. `$data` не допускается
в params: источники остаются независимыми, граф выполнения не вводится.
Существующий legacy ключ `content` не переписывается; новое управление таким
подключением блокируется с диагностикой коллизии и доступом к Structure.

## 5. Формы и типы

Поддерживаемые literal-параметры: string/text, number, boolean и enum по схеме,
включая default, min/max, integer, maxLength/enum там, где они объявлены.
Optional параметр можно не задавать; explicit null разрешён для `required != true`
по действующему `fieldValue`, отдельный флаг nullable не вводится. Отсутствие
параметра применяет default, а explicit null не заменяется default.
Object/list/ref/asset/richText параметры не получают универсальный JSON-редактор:
источник с обязательным неподдержанным параметром без default недоступен для
нового подключения; существующее подключение остаётся читаемым без потери полей.

Пути выбираются из контрактов: прямые поля и вложенные object-поля до глубины 8,
до 200 отображаемых путей с сообщением о пределе. Списки нельзя проходить индексом,
entity-reference не разыменовывается. Источники параметров ограничены `$content`
scalar/object leaf, существующим локальным text и `$context.locale`.
Параметры не получают `$item`, `$data` или контекст native-предка: загрузка
документная и предшествует рендеру. Другие существующие operands сохраняются
в read-only режиме; новая форма не заменяет их при изменении соседнего поля.

Совместимость повторяет bindingdoc и правила предыдущего пакета, включая nullable,
required, enum, диапазоны и assetKind. Не выполнять неявные преобразования
number→text, object→string и asset→URL. `$item` целиком можно связать с object prop
только при структурной совместимости; это позволяет использовать существующую
native-карточку без component.extract. Для Image.src сохраняется `{assetId}`;
подписанная модель формируется server helper и не записывается в документ.

Repeat создаётся отдельным действием в панели/палитре для выбранного списка.
Мастер предлагает ключ из обязательных string/number полей item; `$item.id`
предлагается первым, если подходит. Без подходящего поля доступен только явный
индекс с пояснением. Вставка не копирует готовые данные ответа в IR. Для объекта
без списка действие недоступно. Для paginated result путь items синтетический,
cursor не показывается как контент и не сохраняется в params/IR.

Канонический формат новых key — `$item.<path>`, как у runtime и витрины.
Ранее сохранённый bare path `id` должен одинаково читаться сервером и runtime
как эквивалент `$item.id`, без скрытой перезаписи IR. Другие выражения ключа
недоступны для нового выбора. Добавить общие фикстуры обоих форматов, отсутствие
поля, null, дубли и строковый/числовой ключ. Ошибка ключа ограничивает конкретный
Repeat, не обрушает независимую часть страницы.

Выбор источника списка у существующего Repeat проверяет все его children и
empty; исчезновение/изменение типа поля блокирует подтверждение либо требует
явного снятия поддерживаемых привязок одной группой. Перемещение поддерева
за границу item scope не оставляет тихо неработающий `$item`. Вложенные legacy
Repeat и `$each` читаются и сохраняются без уплощения; неоднозначное изменение
области блокируется с указанием пути. Empty редактируется через дерево даже
при непустом списке; вставка в empty использует обычные правила slot/allowedTypes.

## 6. Загрузка, preview и публикация

Manifest содержит контракт, не реализацию. Существующие `loadSource`/
`preparePageWithData` и server helper исполняют только registry приложения.
Новый произвольный endpoint CMS для проверки loader не нужен. Studio показывает
ошибки из preview и состояние контракта; credentials/код/сырые ответы загрузчика
не пересылаются в панель. Авторизация данных приложения остаётся его серверной
обязанностью; наличие источника в manifest не даёт пользователю доступ к данным.

Сохранение dataSources вызывает существующий полный server reload preview.
Изменение выбранной сущности тоже инвалидирует источники, использующие её поля.
Scope.content отделяется от `$data`, а ключ `content` не перезаписывает primary
content при объединении результатов. Данные не берутся из глобального каталога
или последнего результата другой страницы/CS/локали. Кэш исходного CMS page
и ETag не объявляются кэшем внешнего loader: общий кэш/TTL и зависимость ETag
от внешнего сервиса остаются вне пакета; перезагрузка исполняет loader заново.

Runtime сохраняет независимые разделы при `CMS_SOURCE_UNKNOWN`,
`CMS_SOURCE_TIMEOUT`, `CMS_SOURCE_ABORTED`, `CMS_SOURCE_PARAMS_INVALID`,
`CMS_SOURCE_RESULT_INVALID` и `CMS_SOURCE_FAILED`. Для зависимого Repeat показывается
недоступность с кодом источника, а не empty slot. При валидных `[]`/`items: []`
показывается empty; missing/null вместо объявленного списка — ошибка.
Начальная загрузка имеет видимое состояние; при неудачном обновлении допустим
последний успешный preview с явной пометкой устаревания, без ложного «сохранено
и отображено». Поздний ответ отменённого запроса не применяется.

Preview design выбирает узел и не запускает действия; interact сохраняет
существующий контракт приложения. Клиент получает только подготовленный plan
для SSR/гидратации и обычные preview attributes; published DOM их не содержит.
Параметр `$context.locale` и `$content` используют одну точную локаль. Ранее
реализованный image delivery, безопасная заглушка и обновление подписанных URL
с локалью обязательны также для картинок из item.

При публикации проверяются имена источников/параметров, result paths, item scope,
совместимость свойств и контракты manifest именно целевого окружения. Неизвестный
source/поле не пропускаются как валидный источник. Доступность внешнего сервиса
не проверяется исполнением loader внутри транзакции публикации: runtime-сбой
остаётся безопасным состоянием витрины. Согласование, просмотр diff и защита
решения по снимку остаются действующими для всего CS.

## 7. Проверки и критерии готовности

Каждое STU-219…236 получает тест/фикстуру с ID по [правилам](testing.md).

| Уровень           | Обязательные сценарии                                                                                                                                                                                                   |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Go / PostgreSQL   | Операция add/replace/remove, strict payload, reserved keys, пустая map/inverse, атомарность, seq/retry, undo/redo/rebase; page-only, права/политики и закрытый/чужой CS; изменение manifest и publish target            |
| Go/TS conformance | DataSourceUse и operands; result/paginated path; key bare/canonical, nearest item/empty, nested legacy, moving scopes; одинаковые type/path и publication diagnostics                                                   |
| Runtime / React   | SSR/гидратация без повторного loader, параллельность/timeout/abort, невалидные params/result, empty против error, плохие keys без потери соседнего блока, подписанные изображения и локаль                              |
| Studio            | Формы/default/null/unsupported, typed picker, добавление Repeat/empty, selection экземпляра, dependency guard, dirty guard, atomic history/retry, конфликты и read-only, Structure diff; RU/EN, фокус/клавиатура/375 px |
| Реальный браузер  | Новый источник/Repeat/bindings через UI, working против published, item заголовки/изображения, пустой список, сбой и повтор, смена Collection/локали, поздний ответ, согласование вторым человеком и публикация         |

Для STU-236 используется настоящий CMS/PostgreSQL, подписанный локальный OIDC
двух людей, React-витрина и доступный object storage/image delivery. Схема,
роли, окружение и код registry могут быть подготовлены API/кодом. Collection,
подключение источника, параметры, Repeat, привязки item и empty создаются через
Studio. Предзаполненный Repeat/готовый binding JSON или подставленный в браузер
массив не заменяют приёмку. Статическую начальную раскладку можно подготовить API.

Приёмочный source объявляет Collection handle и limit, возвращает типизированные
карточки с устойчивым id, title и image; приложение разрешает только свой каталог.
Для RU/EN проверяются точные значения, `naturalWidth > 0`, отсутствие draft до
публикации и новый публичный браузер после неё. Пустой handle-набор и управляемый
сбой loader проверяют разные состояния. Отдельная фикстура покрывает paginated
первую порцию/hasMore без кнопки loadMore. Отчёт фиксирует SHA, manifest hash,
CS/page версии, сценарии и ограничения среды без секретов.

Порядок реализации: согласование key и операция/inverse/rebase → формы params
и зависимостей → data/item picker и Repeat/empty → preview/runtime ошибки
и изображения → двухпользовательская приёмка. Перед PR: целевые проверки,
генерация затронутых контрактов, `go tool sqlc generate` при изменении SQL,
`go build ./...`, `pnpm check` и зелёный CI конечного SHA без снижения порогов.
Ограниченные/прерванные проверки не считаются пройденными.

## 8. Статус и зависимости

Реализованы серверная операция по ключу с inverse/rebase, проверкой standard CS,
прав и locked-зависимостей, формы параметров и каталога, строгий data/item picker,
Repeat с шаблоном и empty, явное снятие зависимых привязок, JSON diff и история.
Go и runtime одинаково понимают `$item.id` и legacy `id`. Отзыв `content.read`
у автора операции повторно проверяется перед публикацией. Loader исполняется
только серверным registry приложения. Сбой источника отличается от пустого
списка, сохраняет соседние разделы и выдаёт безопасный код. Preview отменяет
старый запрос при смене локали и игнорирует его поздний результат.

Локально пройдены генерация контрактов, форматирование, ESLint/gofmt,
TypeScript и Go vet, сборки сервера/Studio/витрины, весь обычный набор Go-тестов
с временным PostgreSQL через testcontainers и целевые интеграционные проверки
новой операции/отзыва прав. SQL и версия IR не менялись. Все 1199 TypeScript-тестов
прошли с действующими порогами: Studio — 298, runtime — 187, React — 68,
витрина — 115. Пройдены все 60 браузерных регрессионных сценариев.
Studio coverage: statements 92,34%, branches 86,51%, functions 92,16%, lines 93,76%.
Полный `pnpm check` в Windows остановился только на Go `-race`: нет CGO.
Linux race и общий порог Go coverage 95% должны пройти в CI конечного SHA;
локальная проверка не заменяет этот gate. Пороги не снижались.
