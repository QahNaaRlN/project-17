# ADR-0017. Один процесс cms serve и границы модулей без depguard

Статус: принято · D-42 · Глава: 12 §1.2, §5 · Требования: —

## Контекст

12 §1.2 описывает режимы `serve`, `worker`, `migrate`, модули (`content`, `schema`, `design` …), публичные интерфейсы `internal/<module>/api.go` и линтер `depguard`. Бинарник `cms` имеет режимы `serve`, `migrate`, `bootstrap`, `version` и служебные; задачи River выполняет `cms serve`; пакеты `internal/*` разделены по функциям (`changes`, `workflow`, `publishing`, `delivery`, `capabilities` …), запросы к БД — через общий слой sqlc `store`.

## Решение

Один процесс обслуживает API и задачи; масштабирование — числом реплик `cms serve`. Границы модулей держатся ревью и тестами пакетов.

## Рассмотренные варианты

- Отдельный `worker` — второй процесс без нагрузки, которая его требует (нагрузочные тесты зелёные).
- `depguard` по `api.go` — переписывание всех пакетов вокруг интерфейсов без найденной проблемы.

## Последствия

- Глава 12 §1.2 и §5 описывают фактическую структуру; пересмотр — если задачи начнут влиять на задержки API.
