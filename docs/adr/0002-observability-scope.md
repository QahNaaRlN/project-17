# ADR-0002. Логи в stdout; ошибки действий браузера не отправляются

Статус: принято · D-27 · Глава: 01 §3, 12 §4 · Требования: NFR-018, OPS-023

## Контекст

NFR-018 требует экспорта трассировок, метрик и логов через OpenTelemetry; OPS-023 — отправки диагностик runtime, включая ошибки действий. Пакет [наблюдаемости](../observability.md) принял решения §11.3 и §11.4.

## Решение

Трассировки и метрики экспортируются по OTLP/HTTP. Логи — JSON в stdout с `traceId`, `spanId`, `projectId`, `actorId`; их собирает агент окружения (Collector filelog, Docker, хостинг). Диагностики runtime отправляет только серверная часть приложения (`@cms/react` после SSR опубликованной страницы); ошибки действий в браузере не отправляются.

## Рассмотренные варианты

- Экспорт логов по OTLP — зависимость от бэкенда до выбора хостинга.
- Телеметрия из браузера — открытая точка входа с ключом доставки в клиенте.

## Последствия

- Глава 12 §4 описывает фактическую схему.
- Пересмотр: при выборе хостинга (логи) и при появлении ключа телеметрии без прав чтения (браузер).
