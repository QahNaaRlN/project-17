# Архитектурные решения (ADR)

ADR фиксирует отступление реализации от спецификации или решение, которое меняет её
текст ([сверка](../spec-reconciliation.md), STU-614…617). Реестр
[13](../spec/13-decisions.md) ссылается на каждый ADR строкой D-xx; матрица
[прослеживаемости](../spec/traceability.md) — у каждого требования со статусом
«выполнено с отступлением», «отложено» или «снято».

## Когда писать ADR

- Реализация расходится с требованием уровня ДОЛЖЕН, НЕ ДОЛЖЕН или СЛЕДУЕТ либо с описанным в главе устройством.
- Требование MVP не реализуется в MVP (статус «отложено») или отменяется («снято»).

ADR не нужен для уточнения, которое не меняет требований (например, выбор протокола
экспорта из допустимых): его достаточно описать в документе пакета.

Файл — `NNNN-краткое-имя.md`, номера не переиспользуются. Статусы: `принято`,
`отложено до <этап или условие>`, `заменено ADR-NNNN`. В том же PR правятся глава
спецификации, строка матрицы и реестр 13; `pnpm spec:check` проверяет ссылки.

## Шаблон

```markdown
# ADR-NNNN. Заголовок

Статус: принято · D-xx · Глава: NN §N · Требования: XX-NNN

## Контекст

## Решение

## Рассмотренные варианты

## Последствия
```
