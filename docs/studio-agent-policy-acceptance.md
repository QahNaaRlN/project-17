## Реализовано

- Документ политики v1 (`internal/agentpolicy`): правила `allow`/`deny`/`requireApproval`
  с субъектом `*` или именем агента, правила риска и согласований, условия
  `environment`, `pathPrefix`, `zoneMode`, `zoneId`, `operationType`, `schema`,
  `risk`, `source`; строгий разбор, лимиты и проверка значений проекта.
- Чистое вычисление AGT-010/011: потолок, `deny` сильнее `allow`, без подходящего
  `allow` действует потолок (§11.6), `environment` — любая цель для `deny`, все цели
  для `allow`/`requireApproval` (§11.4), правила с `risk` — только на этапе 5.
- Миграция 00027: `agent_policy_versions` с переносом `settings.agentPolicy` в
  правило `legacy`; `changesets.policy_approval`.
- `set-agent-policy`: неизменяемые версии с автором, причиной и хэшем,
  `expectedVersion` (`POLICY_VERSION_CONFLICT`), `POLICY_INVALID` с полем и причиной;
  старый payload `{allow, deny}` сохраняется как правило `legacy`.
- Query: `GET /agent-policy` (версия и допустимые значения форм),
  `GET /agent-policy/versions`, `POST /agent-policy/explain` (dry-run, project.admin).
- Проверка каждой операции агента в `apply-operations` до записи и
  `create-capability-request`: `403 POLICY_DENIED` с `right`, `ruleId`, `condition`,
  `operationIndex`, `reason`; те же поля в `security_events`; квота за отказ не
  списывается; `requireApproval` ставит метку CS.
- Этап 5 и публикация повторно вычисляют текущую версию: запрет делает проверку
  `policy` проваленной с правилом; правила риска и согласований поднимают риск,
  число и роли согласующих. Новая версия политики перепроверяет поданные CS агентов.
- Агент: MCP получает код, правило, условие и безопасный текст; шаг встроенного
  Agent хранит причину отказа.
- Studio: раздел «Политика агентов» (project.admin) — формы правил прав, риска и
  согласований, «Проверить политику», история версий с автором, причиной и diff,
  сохранение с `expectedVersion` и reason, точный повтор, dirty guard, RU/EN;
  причина отказа в шаге агента; карточка проверки показывает метку согласования и
  отказы текущей политики.

## Отступления и уточнения при реализации

| Тема | Решение | Основание |
|---|---|---|
| Идентификатор зоны | `zoneId` — id ближайшего узла с объявленной зоной (`zone`) | В IR зона объявляется на узле; отдельного идентификатора зон нет |
| Схемы в условиях | Допустимы схемы, известные проекту (`schema_versions`) | Схемы публикуются версиями; список активного manifest вычисляется из них |
| Правила риска/согласований | Применяются ко всем CS; условие `source` сужает их до операций агента | STU-437: правила с `source: agent` затрагивают только CS агентов |
| Публикация при запрете | Публикация отклоняется `POLICY_DENIED`; перевод в `failed` выполняют этап 5 и сохранение новой версии | Отклонённая транзакция публикации не может записать состояние |
| `requireApproval` в приёмке | Правило для окружения `staging` | На стенде одно окружение `staging` |
| Повторная проверка при сохранении | Перепроверяются CS в `in_review`/`approved` с операциями агентов | STU-430: запрещающая версия переводит CS в `failed` сразу |

## Автоматические проверки

- Go: табличный тест AGT-010, проверка документа, риск/согласования/потолок,
  версии, конфликты, idempotent retry, legacy, dry-run, HTTP-маршруты и MCP,
  отказ пакета с индексом и событием, метка согласования, контекст сущностей,
  схем, создания и смены маршрута, этап 5, публикация, перепроверка при новой
  версии, встроенный Agent, инъекции сбоев таблицы версий.
- CI-эквивалент в Linux-контейнере: `go test -race` с PostgreSQL — зелёный, кроме
  `assets`/`imagedelivery` (нет S3/imgproxy в контейнере); покрытие Go 95.08% в
  контейнере (в CI обычно на 0.1 выше; порог 95%).
- TS: модель и API политики, панель (формы, сохранение, точный повтор, конфликт,
  проверка политики, история), BFF-маршруты, причина в шаге агента, карточка
  проверки; ESLint, typecheck, Prettier; покрытие Studio выше порогов.

## Не проверено

- Встроенный Agent с реальным провайдером (отказ в шаге проверен тестом с
  фиктивным провайдером).
- Несколько окружений в одном CS на стенде (покрыто тестами вычисления).
- Продакшн-хостинг.
