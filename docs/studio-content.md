# Studio: сущности, RichText v1 и ассеты

Пакет после PR #45, STU-100…104. Панель «Контент» работает в уже открытом
стандартном CS страницы. Сущности и ассеты используют тот же CS, seq, историю,
проверки и явную публикацию. Контент не требует ручного ввода ID.

| ID | Контракт |
|---|---|
| STU-100 | Каталог сущностей/ассетов по проекту и текущему CS: working версия перекрывает head; чужие неопубликованные объекты исключены. Фильтр схемы, пагинация по UUID, видимые tombstone текущего CS для восстановления. Полное чтение проверяет актуальную схему окружения; несовместимая версия диагностируется, без неявного upcast. |
| STU-101 | Формы строятся по manifest-схеме: scalar, локализованные значения, reference/asset с выбором из каталога, object/list/link через структурный JSON. Неизменённые поля/локали сохраняются точно; отсутствующее значение отличается от null/пустого. Создание, set/unset, delete/restore требуют явного действия и серверных прав. Missing required допускается как предупреждение черновика; manifest и ссылочную целостность окончательно проверяет сервер. |
| STU-102 | RichText v1 хранится только структурным JSON. Редактор блоков/инлайнов сохраняет marks и вложенность, использует ограничения blocks/marks схемы. Все блоки/marks v1 доступны через структурный режим; HTML не импортируется. Runtime/React поддерживают RichText с безопасными ссылками, экранированием текста и проверкой ограничений. Изображения используют предоставленные приложением подписанные image models; без модели показывается alt. Page-ссылки требуют resolver приложения. |
| STU-103 | Каталог ассетов, metadata alt/title/focalPoint/tags, ссылки из схемных полей. Загрузка: SHA-256, create-upload → PUT в явно настроенный assetUploadOrigin → complete → статус → явное asset.create/replaceFile в CS. Неопределённый ответ повторяется с тем же ключом/телом; готовность файла не публикует его. URL загрузки не показывается и не пишется в журнал. Авторизация/CSRF/Origin и серверные MIME/размер/готовность проверки сохраняются. |
| STU-104 | Несохранённый контент блокирует уход и другие правки. База CS/seq фиксируется при начале ввода; stale требует явного сброса, автоматического rebase нет. Одно сохранение — атомарная группа, undo/redo восстанавливает данные/локали/метаданные и обновляет каталог/preview. Отказ/конфликт/потерянный ответ перечитывают сервер; исход неизвестен — новые команды блокируются до чтения или проверки того же запроса. Смена работы/актора уничтожает старый буфер и отменяет запросы. Read-only чужого/закрытого CS, ru/en, клавиатурные формы. |

Каталог и чтение используют head как базу Command Bus; environment выбирает
контракт CS, а не опубликованную версию. CS должен принадлежать проекту и иметь
выбранный environment среди targets. Чужой CS доступен для чтения при content.read,
запись по прежним правилам владельца/правам. Размер каталога 50; фильтры применяются
до LIMIT. Данные карточек не включают binary URL или signed URL.
Каталог возвращает только `locales`/`defaultLocale` из настроек проекта, без
остальных settings. Формы используют объявленные локали и сохраняют остальные
значения. Заголовок карточки берётся из `title` (defaultLocale, ru/en либо scalar),
иначе показываются схема/вид и краткий ID; произвольный display.titleField пока
не используется. Контракт формы фиксирует manifestHash вместе с CS/seq.
Для существующего объекта Studio передаёт `expectedVersionId`: Command Bus атомарно
сравнивает исходную working/head версию до первого изменения в группе.
Изменённый head другого CS даёт `CONTENT_VERSION_CONFLICT` (409), без новой
рабочей копии, операций и изменения seq. Dirty-буфер сохраняется до явного сброса.
`entity.setFields` проверяет первый target CS: если он отличается от окружения
Studio, эта панель доступна для чтения. Нужен CS с первым target этого окружения.

`listItem` — структурный ребёнок разрешённого bulletList/orderedList, без
отдельного разрешения в `blocks`. Самостоятельный listItem в doc/blockquote
не допускается. Go и TypeScript применяют одинаковое правило.
Создание сущности/ассета, как и раньше в Command API, не имеет inverse и даёт
`UNDO_NOT_SUPPORTED`; редактор показывает причину в истории. Правки полей,
метаданных, замена файла и delete/restore используют существующие undo/redo.

Пакет не реализует locale fallback/upcast, параллельный перевод, редактор схем,
изменение document.content деклараций, локальный richText через localContent.set,
CDN/deploy или настройку реального S3/IdP. JSON страницы продолжает редактировать
только локальный text. [SSE/presence](studio-realtime.md) реализован; следующий пакет — Agent.

Приёмка: каталог → создание сущности → поля/локали/rich text → сохранение →
history/undo/redo/reload; metadata/выбор ассета → загрузка/обработка → явное
добавление/замена; schema/rights/stale/rejection/lost response/смена актора.
Pure/DOM, публичный HTTP/Command API на PostgreSQL и Chromium проверяют границы.
Chromium моделирует CMS/IdP/S3 на публичной HTTP-границе; Go-тесты проверяют
реальное хранение, групповой rollback, версии и undo/redo на PostgreSQL.
