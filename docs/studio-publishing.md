# Studio: проверки, согласование и публикация

Пакет завершает основной путь работы со страницей: правка → подача → проверки →
согласование по политике проекта → явная публикация в окружение Studio.
Studio использует публичный Command/Query API и текущего локального актора.
Сервисный актор не может согласовать изменения (PUB-003); интерфейс объясняет
это ограничение и не меняет политику согласований. Production-вход — отдельный этап.

| ID | Контракт |
|---|---|
| STU-070 | Панель показывает серверное состояние CS, все затронутые объекты, риск, целевые окружения, проверки, число/роли согласований и историю решений. Query review возвращает согласованный снимок и доступность действий текущего актора, без тел объектов и секретов. |
| STU-071 | Владелец подаёт открытый CS с expectedSeq; сначала требуется сохранить введённые значения свойств/дизайна. Блокирующие проверки показываются с окружением, объектом, кодом и путём. Переход к существующему узлу текущей страницы доступен с клавиатуры; диагностики других объектов не выделяют похожие ID на текущей странице. |
| STU-072 | Согласование/запрос правок доступны только человеку с content.publish, который не владеет CS и не является автором его операций. Запрос правок требует комментария. Владелец может явно вернуть failed/changes_requested/in_review/approved в работу; интерфейс предупреждает о сбросе согласований. |
| STU-073 | Публикация доступна для approved и content.publish; подтверждение называет CS, окружение и весь список затронутых объектов. Публикуется весь CS, не только открытая страница. Успех показывает подтверждённую публикацию и ссылку на страницу приложения. Никакой автоматической публикации, смены политики, promote или rollback. |
| STU-074 | Все команды используют один сохранённый ключ/тело/expectedSeq для повтора после потерянного ответа; исход не объявляется успешным только по состоянию CS. Пока исход неизвестен, новые правки/команды/смена работы блокируются. После команды перечитываются CS, документ, история и review; смена сессии/отмена исключает применение поздних ответов. Сервер повторно проверяет seq под блокировкой для review/reopen/publish; устаревшие проверки, права, базы, роли и ошибки среды не обходятся. |

Проверки и согласования — снимок последней подачи, не гарантия будущего успеха.
Сервер повторяет необходимые проверки при согласовании и публикации. Ошибки
rebase/конфликтов показаны с дальнейшим действием; мастер разрешения конфликтов,
diff версий, история публикаций/откат, SSE и production identity — следующие пакеты.
